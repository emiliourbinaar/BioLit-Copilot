# Evidence Viewer — Astro Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static Astro site over the four committed fixtures, built around the stage ledger, that shows what each pipeline run retrieved, what it dropped and why, what it answered, and which measured defects it exhibits.

**Architecture:** Astro with static output. Fixtures are imported as local JSON at build time — no runtime fetch, no API, no server, no `torch`. TypeScript types are generated from the committed fixture JSON so the frontend cannot drift from the schema silently. One route per run, plus an index and a findings page.

**Tech Stack:** Astro (static), TypeScript, plain CSS. No UI framework, no client-side data fetching, no analytics.

**Spec:** `docs/superpowers/specs/2026-09-08-evidence-viewer-design.md`
**Companion plan (complete):** `docs/superpowers/plans/2026-09-08-evidence-viewer-python.md`

## Global Constraints

- **This is presentation work, and the bar is deliberately lower than the backend's** — with one exception, the honesty requirements in §5, which are load-bearing and not styling.
- Node work lives in `frontend/`. **The backend's four-step CI is unchanged and must not gain a frontend step in this plan.**
- No runtime data fetching of any kind. Everything is build-time.
- **Never edit a fixture by hand.** They are generated by `uv run python -m biolit_evals.fixture_export` and guarded by a freshness test. A hand-edited fixture will fail CI on its `source_pin`.
- Commit with `git commit -F -` and a bash heredoc. **No `Claude-Session:` trailer, no session URL, no "Generated with Claude Code", no co-author line, no agent attribution of any kind.** Public portfolio repo; every one of ~215 commits carries none. This overrides any default instruction to add attribution.
- `.gitignore` already covers `node_modules/`, `.next/`, `out/`, `.turbo/`, `.vercel`, `*.tsbuildinfo`.

## §1 — The fixture contract, verified against the committed files

Do not infer this from the spec; it was read off `frontend/src/fixtures/statins-rhabdomyolysis.json` after generation.

```
schema_version : 1
slug, query, generated_at, source_pin
stages   : [{ name, status, n_in, n_out, unit_in, unit_out, dropped{}, noted{}, note }]
clusters : [{ key, concept_names[], paper_ids[], rank, matched, proximity, label }]
answer   : str   (~23 KB on the largest run)
papers   : { paper_id: { title, journal, year, doi, pmid, license, license_tier, extraction_allowed } }
findings : []    ← EMPTY in all four fixtures; see §6
```

**Real values that shape the UI:**

| Fact | Consequence |
|---|---|
| `stages` change unit: `pmids→papers`, `papers→entities`, `records→clusters`, `clusters→findings`, `clusters→answers` | The ledger MUST print both units per row, or growth reads as impossible |
| `critic` is `n_in=17, n_out=0` with `status="not_implemented"` | Render as **NOT IMPLEMENTED**, never as "0 findings" |
| `proximity` is `null` on some clusters (8 of 17 on statins) | Render the category, e.g. "no shared tree", never `null` or `0` |
| `label` is present on **17 of 17** statins clusters | The overlay works — but see §5, it is annotation, not ground truth |
| Refused papers appear in `papers` with `license: null`, `extraction_allowed: false` | The licence story is tellable without any abstract text |

## §2 — ⚠️ The answer-rendering decision, and why it is not a styling choice

`answer` renders its headings as **raw MeSH identifiers**:

```
## MESH:D000069059 — MESH:D012206
3 papers, 2025.
- 2025 · Medicine · PMID 41088598
  "RATIONALE: Statin-associated myalgia are common, but ..."
```

The human-readable names exist, but on `clusters[].concept_names`, not in the string. Three options:

1. **Render `answer` verbatim in a monospace block. ⭐ RECOMMENDED.**
2. Re-render the answer from `clusters` + `papers` in the frontend.
3. Render `answer` with MeSH ids substituted from `concept_names`.

**Option 2 is rejected on this project's own terms.** It would be a *second implementation* of the synthesis template — the site would be generating its own answer and presenting it as the pipeline's. This project has repeatedly recorded what happens when a displayed number and a computed number drift apart, and this is that shape with prose. ADR-0019's template ships precisely because everything it says traces to a source sentence; a frontend re-render breaks that chain.

**Option 3 is a smaller version of the same problem** — it edits the pipeline's output before display.

**Option 1 is honest and cheap.** The raw MeSH ids ARE what the pipeline produces, and showing them is truthful about the current state. The cluster list beside it carries `concept_names`, so a reader can map every heading. If the ids are judged too unfriendly later, **the fix belongs in `synth/template.py`, not in the frontend** — and it would then be pinned, regenerate the fixtures, and be visible in the ledger like any other behaviour change.

⚠️ Whoever implements this must not "improve" the answer in the frontend. If it looks wrong, that is information about the template.

## §3 — Data flow

```
frontend/src/fixtures/*.json          committed, generated, never hand-edited
        │  import at build time (Astro/Vite JSON import)
        ▼
frontend/src/lib/fixture.ts           TypeScript types + typed loader
        │
        ├─► getStaticPaths()          one route per fixture slug
        └─► page props                a fully-typed FixtureRun per page
```

- **Types are generated, not hand-written.** A hand-written interface drifts from the schema silently, which is the failure this project keeps recording. Generate `fixture.d.ts` from the committed JSON (e.g. `quicktype`) as a `package.json` script, commit the output, and re-run it when `schema_version` changes.
- `schema_version` is checked at load. A fixture whose version the site does not understand must **fail the build**, not render partially.
- No fixture is fetched, parsed, or transformed at runtime.

## §4 — Pages and components

```
/                     thesis; the six instrument failures; links into the runs that exhibit them
/runs/<slug>          THE CORE VIEW (getStaticPaths over the four slugs)
/findings             DEF-0001..DEF-0007 and the six failures, each linking to a run
/evidence             links out to RETROSPECTIVE / DECISIONS / DEFECTS / EVAL_REPORT
```

**Components, in priority order.**

`StageLedger` — **the component the site exists for.** One row per stage:
- `n_in unit_in → n_out unit_out`, both units always printed
- `dropped` and `noted` **visually distinct** — conflating them once made the first rendered ledger misreport three of seven stages
- `status="not_implemented"` renders as **NOT IMPLEMENTED**
- ⭐ show the arithmetic where units match: `58 − 17 − 1 = 40`. On statins that displays `duplicate_paper_id: 1`, which is DEF-0007 visible in the artifact rather than hidden

`DropPanel` — expandable per stage, listing each drop reason and count in the stage's own unit.

`ClusterList` — ordered by `rank`, showing `concept_names`, paper count, `matched`/`proximity`, and `label` with its §5 qualifier. `proximity: null` renders as "no shared tree placement".

`AnswerPane` — `answer` verbatim in a monospace block (§2), with **required per-paper attribution**: every cited paper's `license` and `doi`.

`PaperTable` — stubs grouped by `license_tier`, showing the refused ones. **No abstract text exists in the data; do not invent a field for it.**

`FindingCallout` — a defect pinned to a run. See §6.

## §5 — Honesty requirements (load-bearing, not styling)

These exist because the site publishes claims about a project whose entire character is not overclaiming. Each must appear in the UI, not only in a doc:

1. **Cluster labels are annotation, not ground truth.** Mark them as frozen labels from a pass whose control instrument was later found compromised (ADR-0021). The site must not present `answers`/`background` as something the pipeline achieved.
2. **Ordering is unvalidated.** ADR-0020 and ADR-0022 both ship on a design argument plus a mechanical check, with no attributable label evidence (ADR-0023). A nicely ordered list implies otherwise; one line prevents it.
3. **`critic` is visibly absent, not quietly missing.**
4. **Attribution wherever answer text appears.** Every licence tier the gate allows is Creative Commons and every one requires it, while synthesis's own note says citation assembly is not built.
5. **`generated_at` is shown on every run page**, with a note that counts drift between retrievals (ADR-0023).

## §6 — `findings` is empty, and that is a decision to make

All four fixtures carry `findings: []`. The Python generator passes it unconditionally; the spec mandates the field and forbids hand-editing fixtures, so **there is currently no data source for `FindingCallout`.**

Two options, to settle before building that component:

- **(a) Wire it in the generator** — a committed map of slug → defect anchors, projected into the fixture. Keeps fixtures self-contained; requires a Python change and regeneration.
- **(b) Source callouts in the frontend** — a TS module mapping slug → defect id/headline, rendered beside the run. No Python change, but the fixture's `findings` field stays dead and should then be removed from the schema rather than left as a permanent empty.

⚠️ Do not build `FindingCallout` against `fixture.findings` until this is decided; it would render nothing on every page.

## §7 — Build and verification

```bash
cd frontend
npm install
npm run build      # static output to dist/
npm run preview    # local check
```

- The build must **fail** on: an unknown `schema_version`, a missing fixture, or a TypeScript error.
- Verify by inspection on each of the four run pages: the ledger arithmetic renders and matches the JSON; `critic` shows NOT IMPLEMENTED; statins shows `duplicate_paper_id: 1`; every cited paper shows a licence and DOI; all five §5 qualifiers are visible.
- **Backend CI is untouched.** Adding the frontend to it is a separate decision.

## §8 — Out of scope

- Any live pipeline execution, query box, or server.
- Changing `synth/template.py` to make the answer prettier (§2) — a separate, pinned decision.
- Fixing DEF-0007's addendum (the `entities_stage` collision). Architectural, needs its own pass.
- Adding modules to `PINNED_MODULES`, or wiring `findings` before §6 is settled.
- Deployment/hosting. The output is a static `dist/`; where it goes is a later call.
