## ADR-0019 — Gate A closes as a negative result about the GATE, not the arm: a deterministic metric suite with no gold cannot certify generative quality once brevity and coverage alone can be gamed. The template ships.
- **Date:** 2026-09-04
- **Status:** Accepted — **Gate A's comparative axes (DCR, compression) are retired as decision criteria. The deterministic template becomes the Synthesis stage.** No paid API call was made at any point: the LLM arm was never authorised, never run, and never estimated. The only network traffic was free NCBI `efetch`. **The gate's design failure was established for $0.**
- **Context:** Gate A asked whether an LLM synthesiser earns the Synthesis slot over `biolit.synth.template`, using a metric suite with **no gold standard at all** — the premise (spec of 2026-09-03 §1) being that a claim is checkable because the source text is right there, which is what makes the gate free and what made it attractive after ADR-0017 and ADR-0018 closed two annotation-dependent routes. The suite: support, coverage and entity-hallucination as DISQUALIFIERS (the template scores perfectly on all three *by construction*, so they cannot be comparative — ADR-0015's lesson applied in advance), leaving **DCR and compression as the only comparative axes**. The harness was built subagent-driven across 8 tasks with per-task review plus a whole-branch review, and is recorded in a 32-entry decision ledger where every entry carries a stated cost-if-wrong. It was run end-to-end on 30 real clusters frozen from 8 free PubMed queries (470 papers, `sample_hash fc0c2624f1ffd878`, seed 20260903). The template's measured baseline: support 1.0, coverage 1.0, hallucinations 0, DCR 1.0, compression 1.1417.
- **Decision:** **Retire DCR and compression as decision criteria and ship the template**, on evidence that the two axes rank outputs in the *opposite* order to their quality. ⭐ **THE GENERALIZED SHAPE, and the reason this ADR is written at this level: a deterministic metric suite with no gold cannot certify the quality of generative output once brevity and coverage alone can be gamed. This is a STRUCTURAL LIMIT, not a tuning gap.** Without gold, every axis must be computed from the source text, so each one necessarily measures *overlap with the source* — and overlap-based axes are all maximised by the same degenerate strategy: name every paper, say almost nothing about any of them. Two measurements make it concrete. **(a) DCR saturates at one word.** It marks a paper retained if ANY of its distinguishing tokens survives, and papers carry a **median of 19** such tokens; an arm keeping 1, 2, 3 or 5 tokens per paper scores DCR **1.0000** every time. Its entire dynamic range lies between "zero words about this paper" and "one word about this paper" — it is a second coverage metric wearing a retention metric's name. **(b) compression has no content floor** and rewards brevity monotonically. Consequently an **`index` arm** emitting literally `- PMID x: <one word>` per paper scores coverage 1.0, hallucinated 0, DCR 1.0 and compression **0.0516** against the template's 1.1417 — it characterises nothing and **dominates the template on both comparative axes** — while a genuine synthesis arm fails the §3.1 tolerance on **28 of 30 clusters**. The missing ingredient is a *content floor*, and there is no way to derive one from the source alone: setting a minimum retained-token count is an unjustified threshold, and deciding whether an output says something worth saying requires exactly the annotated gold this design existed to avoid. Note also that the gate had quietly become undecidable in the other direction: since no summariser can exceed the template's compression of 1.14 from above, the pre-registered default outcome ("ship the template") was reachable only via a disqualifier firing — **ADR-0015's tautology having changed sides**, with the LLM arm now scored on a population it could barely lose on.
- **Alternatives:** *Add a content floor to compression* (rejected — the threshold is underivable from source text alone; inventing one would be the "move a threshold to match an observation" this project forbids, and §3's own pre-registration forbids it explicitly). *Introduce annotated gold for characterisation quality* (rejected here, not forever — it is a real option, but it converts a free one-day gate into an annotation programme of the kind ADR-0017 and ADR-0018 already closed twice, and it must be chosen deliberately rather than as a rescue). *Score readability or "would a person prefer this"* (rejected — ADR-0017's explicitly forbidden metric). *Run the pilot anyway to see what the LLM does* (rejected — the axes cannot rank the result, so the run would buy a number nobody could act on; spending to confirm an already-demonstrated design failure is the opposite of what §7's three-step authorisation exists for). *Ship nothing and leave Synthesis a stub* (rejected — the template is measurably faithful and was always the pre-registered default).
- **Consequences:** The Synthesis stage exists and is deterministic: `synthesis_stage` renders every cluster, makes no agreement/disagreement claim (ADR-0018), and invents nothing measurable — support 1.0, coverage 1.0, hallucinations 0, and no judgment vocabulary it was not handed, over 30 real clusters. Citation assembly remains unbuilt (ADR-0013: `Citation` has no consumer). **DCR and compression are retained in code but marked, loudly, as descriptive-only** — deleting them would make the committed run log unreadable, and they are the evidence for this ADR. **Four implementation defects found by the whole-branch review were fixed regardless of the gate's fate**, because the template's own reported numbers must be accurate: a Unicode-normalisation class that flagged a correct ASCII rendering of a Greek-lettered entity as hallucinated (`TGF-beta1`), a judgment-language laundering path where membership was mistaken for use, a coverage cross-product that credited a paper the output never mentioned (turning a true 0.889 — below the disqualifier — into a pass), and a sentinel-pooling defect on compression. ⚠️ **Every one of those four was reachable only by an arm that rewrites rather than quotes, so the harness's own end-to-end self-test — which runs the control arm — could never have surfaced any of them.** That is the sharpest process lesson here and generalises past this gate: **a self-test on a control arm is structurally blind to defects only the treatment arm can trigger.** One further defect of the same shape is recorded and not fixed, since it is moot for a retired gate: a bare `TNF` resolves to the parent MeSH concept of the source's `TNF-α`, so concept *hierarchy* produces the same false positive by a different mechanism. Finally, the ledger's own record was corrected rather than tidied — Ruling 2's wrong prediction stands beside its dated supersession, and the reviewer overturned three rulings of mine (28, 27, 17) whose reasoning is preserved next to the correction.

## ADR-0018 — The Alamri corpus is retired as candidate Critic gold under its current derivation: both strata read π̂ = 0.60, the lexical filter produced zero separation, and Option B closes for the paper-pair unit
- **Date:** 2026-09-03
- **Status:** Accepted — **the Alamri `YS × NO` derivation is retired as candidate gold. Option B (the search for a real Critic gold standard) closes for the paper-pair unit and reopens only on a structurally different approach.** No paid API call was made at any point in this pass; the only network traffic was free NCBI `efetch`.
- **Context:** ADR-0017 retired the CTD contradiction proxy at π̂ = 0.067 and left Option B — sourcing gold that annotates *claims* rather than curated chemical roles — explicitly open and explicitly unprejudged. Option B ran as four bounded empirical probes, each authorised separately, each measured against real data rather than dataset descriptions. **Six corpora across three structural families** were measured: the claim-verification family (SciFact, HealthVer, NLI4CT), the citation-context family (MultiCite, SciCite), and review-derived claim pairs (Alamri & Stevenson). The first five failed *structurally* and are recorded in the spec of 2026-09-02 §0.1. Alamri did not: it cleared every structural bar, which is why the standing retirement conditional did not fire and this pass was authorised instead.

  **What Alamri had that the others lacked.** 727 derivable contradiction pairs and 1,047 agreement pairs from 24 systematic-review clinical questions; 40.98% class balance, so no 2.52%-prevalence problem; **one** near-duplicate claim pair in the whole corpus, so no SciFact-style negation-twin artifact; 257/259 (99.2%) claims appearing verbatim in their own abstract, so ADR-0017's A2 hazard does not fire; 254/254 abstracts retrievable, confirmed live; zero BC5CDR overlap; 97% original annotator IAA on the `YS`/`NO` assertion; free under CC BY-NC-SA 2.0 UK with no DUA. **Disagreement was discovered, not constructed** — claims were extracted from papers already included in published systematic reviews and assigned against the review's own question, with no annotator writing a negation.

  The remaining risk was therefore not structural but *derived-pair validity*: whether a `YS × NO` pair is a genuine disagreement or two compatible findings separated by population or dose — the exact shape that killed CTD. Two lexical signals were measured over the 727 pairs (differing population qualifiers 34.25%; a claim sharing no key term with its own question 37.96%; either firing 58.46% = 425 **flagged**, neither firing 41.54% = 302 **clean**), and the pass was designed to estimate π̂ **separately per subset**, so the reading would say both whether the gold is valid *and* whether the lexical proxy is an actionable filter. The batch was frozen before any pair was read: seed `20260902`, derived-pair manifest hash `71c8bee3347f01d5` (1,774 pairs), batch manifest hash `6d152f5a689b2bdb` (45 pairs), `cap_paper=1` so **every paper in the batch appears exactly once**, down from a corpus maximum of 22.

- **Decision — the derivation is retired, on a reading that is clean but underpowered, and the distinction is the point.**

  **(1) Gate 1 passed, so the Gate 2 readings are interpretable.** `cant_tell` **0/45**, 95% Wilson [0.0000, 0.0787] → **TRACTABLE**. The annotator could judge these pairs; nothing was swallowed by the escape hatch. This is the precondition ADR-0017 established, and the spec pre-committed that a `REVISE_PROTOCOL` reading would stop the pass without computing Gate 2 at all.

  ⭐ **(2) Both strata read π̂ = 0.6000 — g = 9/15 in each — and the lexical filter produced ZERO separation.**

  | stratum | g | π̂ | 95% Wilson | verdict |
  |---|---|---|---|---|
  | clean (302-pair pool) | 9/15 | **0.6000** | [0.3575, 0.8018] | `CONTINUE_FLAGGED` |
  | flagged (425-pair pool) | 9/15 | **0.6000** | [0.3575, 0.8018] | `CONTINUE_FLAGGED` |

  Fisher two-sided p = 1.0. **This is a measured null on the filter itself, not merely a marginal validity reading**: the §0.3 lexical signals — the differing-population qualifier that encodes the exact dual-pharmacology shape that killed CTD, and the off-question signal — did not identify a subset of the corpus that annotates any better than the subset they excluded. The filter was the one mechanism that could have salvaged a marginal corpus by carving a usable subset out of it, and it carved nothing.

  ⚠️ **The null must be reported with its power, and the power is poor.** By exact enumeration over both 15-pair draws, a Fisher test at n=15/15 would detect a true π_clean = 0.8 against π_flagged = 0.6 only **11.2%** of the time (0.8 vs 0.5: 24.6%; 0.9 vs 0.6: 32.5%). **So "zero separation" is an honest observation from a test that would have missed a substantial real filter effect roughly nine times in ten.** It is evidence against the filter, and it is weak evidence.

  **That underpowering is a design defect, recorded rather than glossed.** Each stratum was fixed at exactly 15 because `evaluate_gate2` refuses any other n — its bands are literal binomial-tail counts calibrated at n=15. That calibration is for a **one-sample stop rule**. It says nothing about the n needed for a **two-sample comparison**, which is what stratifying π̂ turns the design into, and the spec inherited the number across that boundary without noticing the boundary was there. **This is ADR-0017's "the bands do not transfer to another n" arriving from the opposite direction** — there the risk was using the calibrated instrument at the wrong n; here it was using the calibrated n for a question the instrument was never calibrated to answer. The stop rule itself was correctly applied; the *filter* question was underpowered by construction.

  ⭐ **(3) The annotator-strictness confound does NOT apply here. This is the first batch in the project of which that is true.** ADR-0017 recorded as defect (b) that a single annotator cannot separate proxy failure from annotator strictness: Phase 5 applied `insufficient_overlap` to 18 of 30 rows including **4 of 8** gold `agreement` pairs, so the pull was general rather than contradiction-specific and no reading could be cleanly attributed. The five cross-question distractors added to this batch are what make the two separable, and the contrast is unambiguous:

  | control | result | reading |
  |---|---|---|
  | 5 distractors (cross-question, genuinely unrelated) | **5/5** `insufficient_overlap` | the label is used for its meaning |
  | 10 agreement controls (within-question, genuinely related) | **7/10** `agreement`, 2/10 `insufficient_overlap`, 1/10 `contradiction` | **2/10 is far below the pre-committed ≥5/10 strictness threshold** |

  Verdict `DISCRIMINATING`. **Neither π̂ reading is strictness-confounded**, and that is established by a contrast pre-registered before any label existed, not argued after the fact. π̂ = 0.60 is what the annotator actually judged about these pairs, not an artifact of how readily they reach for `insufficient_overlap`.

  ⭐ **(4) This is "do not proceed", NOT "proven invalid", and the two must not be conflated.** The 95% Wilson interval on each stratum is **[0.3575, 0.8018]**, width 0.4443; pooling the strata — legitimate descriptively, and only because they showed no separation — gives 18/30 → **[0.4232, 0.7541]**, width 0.3309. **A genuinely usable π of 0.75 or 0.80 sits inside both intervals.** At n=15 per stratum, π̂ = 0.60 cannot be distinguished from a corpus that would have been fine to use.

  The contrast with ADR-0017 is exact, and it is why the two decisions read differently despite both ending in retirement. There, π̂ = 0.067 with interval [0.012, 0.298] — **the upper bound sat below the 0.70 the design needed, so π ≥ 0.7 was excluded**, a positive finding of invalidity. Here nothing is excluded. The honest statement is: **this corpus's derivation did not clear the bar, and the measurement lacks the resolution to say whether it would have on a larger batch.** Nor is it "probably fine" — 0.60 is also inside the interval, it is the point estimate, and `CONTINUE_FLAGGED` is by the design's own pre-registered definition the band for a proxy that is *merely mediocre* rather than badly failing (P(g ≤ 7 | π = 0.6) = 0.2131, which the spec flagged in advance as deliberately weak). It is squarely a *do not spend against this* under the current derivation, on grounds of insufficient demonstrated validity rather than demonstrated invalidity.

  **The batch lands on §6 decision row 5 — (`CONTINUE_FLAGGED`, `CONTINUE_FLAGGED`): "filter buys nothing; whole corpus marginal → do not proceed."** No cell required rounding and none was rounded; no second batch was drawn on an unwanted reading, which is what a pre-committed stop rule exists to forbid.

  ⭐ **(5) RECOMMENDATION — Option B closes for the paper-pair unit, and should reopen only on a structurally different approach.** Six corpora across three structurally distinct families have now been measured against `ContradictionFinding(paper_id_a, paper_id_b, label, rationale)`. **None produced actionable gold.** Five failed structurally, for reasons that were specific and measured rather than assumed. The sixth — the only candidate that cleared every structural bar, in the right domain, with discovered rather than constructed disagreement, read by an annotator whose label use is demonstrably discriminating — still landed marginal, and the one mechanism that could have rescued it produced nothing.

  **What that pattern supports, and what it does not.** It does *not* establish that no usable paper-pair contradiction gold exists; six corpora is not the population, and this last reading in particular is underpowered. What it does establish is that **the cheap paths are exhausted**: every freely-available corpus reachable without a DUA has now been checked, and the next increment of effort against the paper-pair unit buys a larger annotation batch on a corpus whose point estimate is already only 0.60 — spending real annotation time to resolve an interval around a mediocre number, on the *most* promising candidate of six. **The expected value of that is poor, and ADR-0013's rule — no infrastructure without a demonstrated consumer — applies to annotation effort as much as to code.**

  Reopening should therefore require a *structural* change rather than more of the same, and the most likely one is **abandoning the paper-pair unit itself**. The recurring failure across all six corpora is not that annotators disagree about disagreement; it is that the paper-pair unit asks two abstracts to be commensurable, and real literature separates its findings by population, dose, route, endpoint and time in ways that make most opposed-looking pairs genuinely compatible. That is the same mechanism ADR-0017 named for CTD (dual pharmacology), and it recurred here in a corpus built from systematic reviews *specifically to hold population and intervention fixed* — which is the strongest available evidence that the problem is the unit rather than the source. **A unit that carries the qualifying context explicitly — rather than requiring it to be recovered from two abstracts — is a different task and would need its own spec, not a revival of this one.** That case has not been made here and is not made here.

- **Alternatives:** (1) **Draw a second, larger batch to resolve the interval** (rejected — the design pre-committed that no second batch is drawn on an unwanted reading, and the bands were calibrated so one batch suffices; more importantly the quantity to be resolved is a point estimate of 0.60, so the realistic upside is confirming a mediocre proxy at higher confidence). (2) **Proceed on the clean stratum alone at π̂ = 0.60** (rejected — π is a ceiling, never a correction factor, so a paid arm would be graded against gold whose own validity is 0.60; and the clean stratum is not even the better half, having read identically to the flagged one). (3) **Redesign the lexical filter and re-stratify** (rejected as premature — the filter null is weak evidence, but redesigning a filter to rescue a corpus whose *unfiltered* π̂ is 0.60 optimises the wrong quantity, and the honest reading of the underpowering is that a filter comparison needs ~100 per stratum, i.e. 200+ annotations against a marginal corpus). (4) **Treat the identical 9/15 readings as evidence the strata are truly equivalent** (rejected — P(both land on exactly 9 | a common π = 0.6) = 0.0427, so the exact tie is a coincidence and must not be read as a stronger null than "no separation detected"). (5) **Declare the paper-pair gold search a proven dead end** (rejected — that overclaims; six corpora measured is a strong practical result and a weak universal one, and this ADR says so explicitly). (6) **Keep Option B open and continue searching freely-available corpora** (rejected — the freely-available space reachable without a DUA has been enumerated and checked; continuing means either paying for a DUA-gated corpus or annotating one from scratch, both of which are new decisions rather than continuations).

- **Consequences:** **The Alamri derivation is retired as candidate gold; Option B closes for the paper-pair unit.** Reviving it requires a structurally different unit and a new spec, not a next step.
  **What survives and stays committed.** The derived-pair manifest (`evals/gold/alamri_contradiction_pairs.jsonl`, 1,774 pairs, hash `71c8bee3347f01d5`), the frozen batch (hash `6d152f5a689b2bdb`, seed `20260902`), the 45 annotated labels at `evals/gold/alamri_annotation_batch_1_labels.jsonl`, the run log, and the reusable machinery (`alamri_gold`, `alamri_annotation_export`, `alamri_annotation_gates`). All of it describes a real, reproducible derivation; what is unproven is the *validity* of the label, not the correctness of the construction.
  ⭐ **The 45 labels join Phase 5's 30 as calibration seed, and are the stronger half of that pair.** They are the project's first contradiction judgments made under a protocol with **no strictness confound** — the distractor contrast establishes that positively rather than assuming it — and they carry the annotator's written reason on every row. Any future gold, on any unit, can be checked against them before being trusted.
  ⭐ **Three protocol improvements are established as working and should carry forward to any future annotation pass.** (a) **Cross-question distractors as a strictness discriminator** — the single addition that retired ADR-0017's defect (b), at a cost of five extra rows. (b) **Showing the clinical question rather than a bare shared endpoint** — the fix for defect (a), the endpoint confound; `cant_tell` fell from 1/30 to 0/45. (c) **Layout-tell discipline as an explicit, tested invariant** — three separate tells were found and closed during implementation *because the invariant was written down and tested*: distractor rows showing two questions, a `pair_id` whose shape identified a distractor, and a display order in which `paper_id_a` was always the `YS` paper. Each would have let this batch's sole annotator — who is also its designer — answer a row from its layout rather than its content.
  ⚠️ **One recorded defect against this design, to fix before any future stratified pass.** The stratification was **underpowered by construction**: n=15 per stratum was inherited from Gate 2's one-sample calibration and yields only 11.2% power to detect a 0.8-vs-0.6 filter effect. A stratified π̂ comparison needs its own power calculation — roughly 100 per stratum for non-overlapping intervals at that effect size — and must not silently borrow a number calibrated for a different question. **A calibrated constant is calibrated for one question; carrying it to a second question is a new assumption and needs a new justification.**
  ⭐ **The transferable finding, and it is the inverse of ADR-0017's.** That ADR established that a derived gold label inherits its source's ontology rather than your task's semantics — the label meant something else. Here the label means the right thing: Alamri's annotators genuinely judged whether a paper answers a clinical question yes or no, at 97% agreement, and the pairing is sound. **The failure is downstream of the label, in the inference that two papers answering one review question oppositely are therefore in disagreement** — because the qualifying context that reconciles them (population, dose, route, endpoint) lives in the papers and not in the pair. **A correct label plus a correct pairing can still yield an invalid derivation, and the only way to find that out is to have a human read the pairs before spending anything against them.** That is what both ADRs did, and it is the practice worth keeping regardless of how many corpora it retires.

## ADR-0017 — Phase 5 closes as a negative result: Gate 2 retires the CTD contradiction proxy unspent, and the re-scoped task that would have salvaged it is declined on its own merits
- **Date:** 2026-08-30
- **Status:** Accepted — **Phase 5 is closed. Steps 5–8 (pilot, authorization gate, paid full run) are retired against this gold, not deferred.** No paid API call was ever made **against this gold** — Phase 5's pilot, authorization gate and full run were all retired unspent. *(Corrected 2026-09-01: this line previously read "no paid API call has ever been made in this project", which is false. Phase 4's LLM extractor arm was a real paid run — $2.48 across ~1500 calls, logged in `evals/extract_runs.jsonl` — see ADR-0015. The unspent claim is Phase 5's alone.)*
- **Context:** Phase 5 set out to measure contradiction detection between biomedical abstracts. Gold derived from CTD's `DirectEvidence` direction field: a pair is `contradiction` when CTD records `marker/mechanism` for one paper and `therapeutic` for the other on a shared (chemical, disease) key. The design (spec of 2026-08-19) treated that as a **proxy** and pre-committed a two-tier structure — CTD for scale, blind human annotation for validity — with π, the fraction of proxy contradictions a human accepts as genuine, reported as a **ceiling and never as a correction factor**. Crucially the spec also pre-committed the response to a bad reading, in writing, before any result existed: *"If the first annotation batch reads g ≤ 7, the CTD proxy is failing badly enough that steps 5–8 are not worth buying, and the correct response is to reconsider the gold source rather than proceed with a known-weak ceiling."* The free half of the work was built and run: a 900-pair corpus (pool hash `c3e8bfd78d19b2da`, corpus hash `cd3b394c63a85119`, seed 20260819, CTD release `Thu Jul 30 13:59:07 EDT 2026`), three free baselines, and a blind 30-pair annotation batch.
- **Decision — Phase 5 closes as a negative result, on two independent grounds.**

  **(1) Gate 2 fired. The proxy is measured invalid.** Gate 1 (tractability, all 30 pairs): `cant_tell` **1/30**, 95% Wilson [0.006, 0.167] → **TRACTABLE**. Gate 2 (stop rule, the 15 contradiction pairs, calibrated at exactly n=15): **g = 1**, π̂ = **0.067**, 95% Wilson **[0.012, 0.298]** → **STOP**. The interval's upper bound sits below the 0.70 the design was built to clear, so **π ≥ 0.7 is excluded at n=15**, not merely unsupported — which is the one thing a 15-pair batch has the power to establish, and exactly what the gate was calibrated to detect. Exact agreement with gold is **10/30**, precisely three-class chance. **The two gate readings together are what make this interpretable:** a high `cant_tell` rate would have meant the protocol was unreadable and nothing could be concluded about the proxy. One in thirty says the annotator could judge these pairs perfectly well, and judged them not to be contradictions.

  **Why the proxy fails, and it generalises to any CTD-derived contradiction gold: `marker/mechanism` vs `therapeutic` on a shared key encodes DUAL PHARMACOLOGY, not disagreement.** Disulfiram reduces cocaine use *and* exacerbates cocaine-induced seizures; lidocaine treats tinnitus *and* tinnitus is the symptom signalling accidental intravascular lidocaine injection. Both claims are true in each case, resolved by dose, route, population, or co-administered agent. The *pairing* is sound — spot-checking confirmed both papers really are indexed to the same chemical and the same disease — so it is the **inference from co-keying to disagreement** that breaks. One pair of fifteen was genuine (bretylium tosylate: effective at preventing ventricular fibrillation in one paper, directly inducing it in the other). **CTD's direction field records what role a chemical played in a given paper. That is a curation convention, not a claim another paper can contradict.**

  **(2) The re-scoped task (option A) is declined on its own merits.** With the contradiction label retired, the obvious salvage was to re-scope to what the annotator was effectively answering — *"do these two papers address the same chemical–disease proposition?"* — reusing the existing corpus and baselines. **This is declined, for two structural reasons and one measurement.**

  ⭐ **RESULT A1 — re-scoping hands the task to the free baseline.** `ConceptOverlapCritic` never predicts `contradiction` at all (0 in every row of its confusion matrix); its entire signal is *do these papers share concepts*, which is precisely the re-scoped question. Scored on the binary (same-proposition vs not) against CTD's own labels, over all 900 pairs:

  | arm | three-class | re-scoped binary |
  |---|---|---|
  | `overlap` | macro-F1 **0.3400** (at the measured random floor of 0.3347 ± 0.0186) | accuracy **0.7333**, positive-class P 0.7459 / R 0.9100 / **F1 0.8198** |

  against a majority-class baseline of 0.6667. **The re-scope converts the free concept-overlap heuristic from a chance-level performer into a strong one, and then asks a paid arm to beat it at concept overlap.** That is ADR-0015's shape exactly, where every budget-matched free positional heuristic beat the LLM extractor: it would be buying an arm into a task selected to favour what is already free. This result is recorded as a standalone reproducible number rather than as prose, so a future reader can see the argument without having to trust the reasoning around it.

  **RESULT A2 — the re-scoped task measures the filter, not the judgment.** Being precise rather than claiming redundancy with clustering: Phase 3's same-sentence pairing (paper-pair F1 0.6327) generates *candidates*; the re-scoped task is the *precision filter* on those candidates. Related, not identical, and a real task. But it is not the task the Critic exists to perform. `ContradictionFinding` carries a three-way label because the product claim is "these two papers disagree," and that claim lives entirely on the agreement-vs-contradiction axis — **which is the axis the re-scope deletes from the metric.** A system could score well on it while never once making the call the phase was introduced to make. ⭐ **This is the same failure family as an arm scored on a population it cannot lose on, just arriving from the other direction** — the tautology caught earlier in this same phase when `overlap` posted the best macro-F1 while scoring 0.0000 on contradiction, and the one retracted in ADR-0015. There the metric was computed over a population where the arm could not fail; here the metric would be computed over a decision the arm never has to make. **Both are a score that cannot be lost, and recognising the second from the first is the discipline generalising rather than merely recurring.**

  **MEASUREMENT A3, weaker than A1/A2 and reported with its defect.** The free gold option A would reuse is CTD co-keying (does the pair share both endpoints). Re-analysing the same 30 annotations as a binary gives that label an accuracy of **14/29 = 0.483**, 95% [0.314, 0.656] — **below the 0.621 obtained by always answering "not the same proposition"** — with Fisher two-sided p = 0.68. **This number should not carry the decision, and the reason is stated rather than buried:** those `insufficient_overlap` judgments were made under the three-class protocol *with the endpoint confound below still present*, which pushes an annotator toward "different things" exactly where it damages option A. The honest reading is that **option A's gold is unvalidated and the one available measurement is unfavourable and confounded** — enough to retire the claim that A is cheap, not enough to condemn A by itself. A1 and A2 carry the decision; neither depends on n=29.

  **⭐ A recorded self-correction, kept because the discipline is the point.** When first sketching the options, the controller told the user option A was *"nearly free given what's built."* That claim has a testable premise — A needs gold for "same proposition," and the only free source is CTD co-keying — and it was asserted without running the test. Measurement A3 is what running it produced, and it removes "free" from A's case. **This is a small, concrete instance of the same discipline Gate 2 institutionalises, applied to a claim far below the threshold that would normally attract a check, and applied before it could shape a decision rather than after.** It is recorded here for the same reason ADR-0016 rule 5 preserves the controller's corrected rulings: a decision log that keeps only the claims that were right is not evidence of anything.

  **(3) The recommendation to decline A is explicitly decoupled from option B.** Option B — sourcing gold that annotates *claims* rather than chemical roles, including revisiting SciFact now that its granularity mismatch matters less than a proxy that measures nothing — **is a separate and larger decision, deliberately not designed here and not prejudged by this ADR.** Nothing in A1, A2 or A3 is an argument about B. A is declined because its gold is unvalidated, because it grades a stage adjacent to the one under test, and because it tilts the comparison toward the free baseline. **A reader must not infer from this decision that B is either favoured or disfavoured; that case has not been made and is not made here.**

- **Alternatives:** (1) **Proceed to the paid run anyway and report π alongside the scores** (rejected — π is a ceiling, so at π̂ 0.067 a paid arm would be graded almost entirely on its ability to reproduce a mislabelling: a high score would mean it learned CTD's indexing convention, a low score would mean it correctly declined to call non-contradictions contradictions. **Neither reading is interpretable and both are quotable**, which is precisely the failure the harness exists to prevent). (2) **Annotate a second batch hoping the first was unlucky** (rejected — the Gate 2 bands were calibrated on binomial tails at exactly n=15 so that one batch suffices to detect a badly-failing proxy; re-drawing after an unwanted reading is the thing a pre-committed stop rule exists to forbid, and g=1 is not a borderline reading). (3) **Adjust the gate threshold to admit the observed g** (rejected outright — the project's standing rule is that if an anchor or gate fires, the harness is right and the design is wrong; the mismatch gets reported, never the threshold moved to match an observation). (4) **Build option A anyway as a cheaper consolation deliverable** (rejected on A1/A2 above). (5) **Fold the A decision into a later ADR once B is decided** (rejected — the user asked for A's decline to stand independently of B, and deferring it would create exactly the inference this ADR forbids).

- **Consequences:** **Steps 5–8 are retired against this gold rather than deferred; reviving them requires a new gold source or a re-scoped task, which is a spec change and not a next step.** The `critic_eval` kill-switch runtime-wiring gap recorded during the whole-branch review is thereby **moot unless a paid run is ever revived** — it is retained in the record because its *shape* (a spec requirement owned by no task, ADR-0016 rule 3) is the durable lesson.
  **What survives and stays committed as the salvaged output of the phase:** the frozen 900-pair corpus and its manifests, the three free baselines with the measured uniform-random floor (`overlap` 0.3400 / `lexicon` 0.3252 / `majority` 0.1667 against 0.3347 ± 0.0186 — which also **falsifies the spec's §3 pre-registration that the direction lexicon would score near-ceiling**), the run logs, and `annotation_gates` / `parse_annotations`. They describe a real, reproducible task; only the labels' *meaning* is wrong.
  ⭐ **The 30 annotated labels are preserved deliberately, at `backend/evals/gold/annotation_batch_1_labels.jsonl`, and their role should not have to be rediscovered.** They are the only validated claim-level judgments this phase produced — each with the gold label it was compared against, the endpoint the blind sheet displayed, and the annotator's written reason. They are tiny, and they are **the calibration seed for whatever gold standard comes next**: any future contradiction gold, from any source, can be checked against them before being trusted, which is the check this phase learned to run first rather than last. The sheet itself stays gitignored because it carries full abstract text; the labels carry none.
  **Two defects recorded against the protocol, to be fixed before any re-annotation whatever the design becomes.** First, **the blind sheet's endpoint confound**: showing exactly one randomly-chosen endpoint closed a label leak but stopped telling the annotator *which chemical* a pair turns on (chemical-shown 7/14 exact match vs disease-shown 3/16, Fisher p = 0.12 — a hypothesis, not an established effect). It does **not** change the Gate 2 verdict, and that is checkable rather than asserted: even at the chemical-shown rate across all fifteen pairs, g = 3 against a STOP band of g ≤ 7. Second, **a single annotator cannot separate proxy failure from annotator strictness** — `insufficient_overlap` was applied to 18 of 30 rows where gold has 7, and to 4 of 8 gold `agreement` pairs, so the pull is general rather than contradiction-specific. Note also that **κ = 0.116 here is gold-vs-annotator agreement, not inter-rater reliability**; with one annotator no IRR statistic exists for this batch, and it must not be cited as one.
  ⭐ **The standing generalisation, which is the most transferable thing this phase produced: a derived gold label inherits its source's ontology, not your task's semantics. Ask what question the source field actually answers, and whether it is your question, *before* it becomes gold** — no amount of correct engineering downstream repairs a label that means something else. Validate a derived label on a small blind sample before building baselines on it, not after.
  Finally, this ADR is **the inverse of ADR-0015's throughline and belongs on the opposite side of that ledger**, not as another entry in it. That list enumerates claims that shipped because nothing in the pipeline required them to be true. This is a claim that never shipped, because something did: a stop rule written before the number existed, calibrated in advance, and placed where it had to be cleared before money moved. The retracted 127/270 headline is what the same situation looks like without one. **The lesson from that episode was never "check harder afterwards" but "put the check before the claim," and this is the first time in the project that ordering was in place ahead of time rather than added in response to being wrong.**

## ADR-0016 — Five verification rules from Phase 5's build: a green test proves less than it looks like, and a per-task review cannot see a requirement no task owns
- **Date:** 2026-08-21
- **Status:** Accepted — **a standing process rule, checked on every task and every branch**, alongside ADR-0014
- **Context:** Phase 5's eval harness was built as 14 subagent-driven tasks, each with its own scoped review, then one whole-branch review. The work landed clean (453 tests, all gates green), but the *defects found along the way* form a pattern worth recording, because five of them were found by mechanisms the project did not previously have written down, and three were defects in the plan or in the controller's own reasoning rather than in any implementer's code. ADR-0014 already establishes that every operand of a compound condition must be independently exercised, and that the operational test is a mutation. **This ADR records what Phase 5 learned about the limits of that rule and of scoped review.** ⚠️ **A note on citation precision, since it was got wrong repeatedly during this phase:** ADR-0014's Decision text is literally about *compound-condition operand coverage*. Its louder/quieter principle is a **tie-breaker embedded inside that decision**, scoped to deciding whether an unreachable-ish guard should be kept or deleted. Extending it to general input validation is a fair analogy and this ADR does so deliberately — but it is an extension, not a citation, and should be described that way.
- **Decision — five rules, each with the concrete instance that produced it.**
  **(1) Decide by RUNNING the weakened case, never by reasoning about it.** ADR-0014 already says this; Phase 5 is the evidence that it is not optional. Reasoning was contradicted by execution **five separate times**, including twice where the reasoning was confident and written down. The worst instance was in a *verified reference value supplied to an implementer*: `wilson_interval(0, 10)[0] == 0.0` was offered as a fixture pinning the `k == 0` guard, and pins **nothing** — with the guard removed, that formulation returns exactly `0.0` at n=10 anyway. An implementer found it by running the mutation. A second instance inverted the pattern entirely: an algebraically identical reordering of the same formula (dividing each term by the denominator rather than dividing the difference once) flipped **which** n leave a rounding residue, proving the fixture pinned operation order rather than semantics.
  **(2) Mutants must be derived from the SPEC's requirement list, not from the lines the existing tests touch.** ⭐ **This is the rule most likely to be missed, because a thorough mutation pass feels like proof.** Phase 5's LLM pair-judgment arm shipped a five-mutant pass in which every mutant was killed and every mutant targeted a line some test already covered — so it certified the coverage that existed while staying structurally blind to **four brief requirements that had no test at all** (`_MAX_TOKENS` never asserted as sent; the outbound JSON schema never inspected; "unparseable response" covered only for an out-of-vocabulary label and not for malformed JSON; the ruled-out counter's absence unenforced). **Mutation testing validates the tests you wrote. It cannot surface a requirement you never tested.** The reviewer that found this did so by walking the brief requirement-by-requirement asking *"is there a test that would fail if this were violated?"* — rather than reading each test and checking it passes. Adopt that direction of travel.
  **(3) A requirement can be owned by no task, and a per-task review cannot see it.** Three of Phase 5's spec requirements were assigned to no task brief: **Gate 1** (defined in the spec, named in the plan's own file list, and in the title of the task that shipped without it), the **kill-switch's runtime wiring** (the class was built and tested in isolation; the loop that should call it had been frozen by an earlier task), and the **topping-up algorithm** (its pieces compose, the composition and its test do not exist). Each was invisible to scoped review **by construction** — every reviewer sees only its own brief, so a requirement in no brief is in no reviewer's field of view. **This is the concrete argument for the whole-branch review being a separate, mandatory pass rather than a formality**; it found two of the three, and the third only surfaced because the final task's title happened to contradict its own contents.
  **(4) A green test can pin nothing, and the failure is silent by definition.** Four distinct shapes appeared in one phase. **(a) Identity vs equality:** `GoldPair.label` is a `StrEnum`, so a JSON round-trip returns a plain `str` for which `back == original` is **True** while `back.label is ContradictionLabel.contradiction` is **False** — the round-trip test passed while the halting anchor that compares with `is not` would have fired on every manifest loaded from disk. **(b) A check that cannot run:** `assert_no_bc5cdr_pmids` ran against a default-empty exclusion set, so the anchor guarding against scoring papers the NER checkpoint was trained on could not fire; the fix was to log `excluded_pmids_count` so each run states whether the check was armed. **(c) A verification step that is a no-op on its own inputs:** mutation restoration was verified with `git diff`, which reports nothing for an **untracked** file — so for every newly created module the check silently passed without checking. **(d) A baseline that is secretly a clone:** a "concept overlap" arm was wired so both papers of a pair received the same concept set, making it always answer `agreement` — an exact duplicate of the majority baseline, which quietly lowers ADR-0015's "must beat the best free baseline" bar.
  **(5) The controller is not the authority; the review layer exists to correct it, and did — twice.** A ruling asserted that a cache's assertion demanded disjointness and would crash on legitimate reuse; a reviewer read the source and established it was a data-integrity check (`assert cached_text == text`) that would pass silently on a real hit. **The ruling's conclusion happened to survive on better reasoning; its stated reason was wrong.** Separately, a reviewer corrected repeated loose citation of ADR-0014 (see the Context note above). **Both corrections are recorded rather than quietly absorbed, because a decision log that only preserves the decisions that were right is not evidence of anything.**
- **Alternatives:** (1) Fold these into ADR-0014 (rejected — ADR-0014 is specifically about operand coverage within a condition; rules 2, 3 and 5 are about the *limits* of test-level verification and of scoped review, which is a different subject, and overloading it is what produced the citation imprecision this ADR has to correct). (2) Leave them in the branch's SDD ledger (rejected — the ledger is git-ignored scratch tied to one plan; these generalise to any future phase, and the user asked for them somewhere durable). (3) Record only the two most striking rules (rejected — rule 4's four shapes are the ones most likely to recur, precisely because each looks like passing coverage).
- **Consequences:** Every future implementation brief inherits rules 1 and 2 explicitly: mutations are **run** with pasted output, restoration is verified with a **saved-copy `diff`** (never `git diff`, which is vacuous on untracked files), and mutants are selected from the spec's requirements. Every plan gets a **pre-flight conflict scan** producing a written table — one row per pair of tasks sharing a file or interface, one row per task's self-consistency — which is what caught the StrEnum identity defect in Phase 5 *before* any code was written. **The whole-branch review is mandatory and is not a formality**; it is the only pass positioned to catch rule 3, and it must be pointed explicitly at the spec's requirement list rather than at the diff alone. **Phase 5's full ruling record — 30 rulings, each with what it costs if wrong, plus every per-task mutation transcript — is retained at `.superpowers/sdd/2026-08-19-contradiction-detection-eval/progress.md`** rather than deleted on completion, because that evidence exists nowhere in git history and rules 1, 4 and 5 are all argued from it.

## ADR-0015 — The LLM extractor is not shipped: it loses to the first four sentences of the abstract at an identical selection budget
- **Date:** 2026-08-17
- **Status:** Accepted — **supersedes an earlier version of this ADR whose central claim was retracted after review.** The retraction is kept in place of the claim rather than edited away, on the same principle as ADR-0013's refuted "Arm A is a ceiling" note.
- **Context:** Phase 4 asked whether an LLM sentence extractor earns its place over the free deterministic control (`SameSentenceAsEntitiesExtractor`) on BC5CDR Test-500. **An earlier version of this ADR claimed the arm had produced the first measured evidence that this project's twice-priced entity bottleneck was reachable — recall 0.4704 on the 270 `endpoint_lost` sentences. That claim was accepted on a comparison that could not have come out any other way, and it is retracted.** The comparator was `control-real`, which scores **exactly 0** on that population *by construction*: `endpoint_lost` is defined as a subset of control-real's own misses. **A comparator that structurally cannot lose is not evidence, however large the gap it produces.** ⭐ **THE GENERALIZED SHAPE, worth recognizing before it ships again: when an arm is scored on a population defined in terms of another arm's failures, the second arm's zero is a tautology, and the only thing that tests the claim is a baseline matched on whatever the first arm spends.** Two such baselines, both free and both computable from the already-committed run log, overturned it. **(a) A rate-matched null:** the arm selects 2274 of 4885 sentences — 46.55% of the corpus — and under independent Bernoulli(*p*) selection expected recall on *any* gold subset is exactly *p*, so the null is **0.4655 ± 0.0304** against the arm's 0.4704, **z = +0.16**. **(b) A positional baseline, which is the decisive one:** the first four sentences of each abstract, padded at random to the arm's exact budget, scores **0.5496 ± 0.0128** on the same population — beating the arm on **every one of 200 seeds**, worst draw 0.5148 — and beats it on precision, recall and F1 as well. "First 2 sentences", at 44% of the arm's budget, beats its F1 by 30% relative. **The result does not rest on the padding construct**: padding equalises the budget and *lowers* the baseline's precision, and the unpadded `first 4` — at 13% *below* the arm's budget — still beats it on all four columns. Both computations are committed as `biolit_evals.baselines` and run free.
- **⭐ AMENDED 2026-08-18 — the family has since been SWEPT, and the finding is stronger than the sampled version stated.** This ADR originally conceded that `first 2 / first 4 / last 4` was a *sample*, so 0.5496 was a lower bound and the trigger below could be cleared by an arm still losing to an unmeasured neighbour. Seventeen members were then measured: `first k` and `last k` for k = 1…6, plus a length-adaptive `first f%` ladder at f = 10…50. **Two things changed. First, the bar moved only slightly — to 0.5544, `first 2` padded to budget — so the original figure was indeed low, but not by much. Second, and this is the part worth carrying: EVERY budget-comparable member of the family beats EVERY logged arm.** Twelve of the seventeen fit inside the arm's 2274-sentence budget; they span **0.4972 to 0.5544**, and the best arm scores **0.4704**. The weakest free heuristic measured — `last 1`, the single closing sentence of each abstract plus random padding — still beats the arm by 0.027. **This is a different claim from "the arm loses to the opening sentences of an abstract".** It is "there is no member of this positional family the arm beats", which removes the reading that `first 4` happened to be a uniquely well-chosen comparator. **The five members that do NOT fit are excluded on principle, not omitted:** `first 5` costs 2449 sentences against a 2274 budget, so it cannot be padded down, and its higher raw recall (0.5704) is bought with volume rather than with better choices. **The bar is now a closed form, not a maximum over estimates.** Padding draws without replacement, so bucket-(a) hits are Hypergeometric and the exact moments are computable; the previous top two rows were separated by less than two of their own SDs, so which one *was* the bar had rested on the seed range. 200 draws agree with the closed form to within 0.001 on all twelve rows.
- **Decision:** **Do not ship the LLM extractor, in any role.** On the shared task the free control wins decisively — **F1 0.6238 against 0.3054** — because the arm over-selects at 4.55 sentences per paper against 2.31 and pays for it in precision. On the restricted bottleneck population it is **indistinguishable from chance at its own selection rate, and loses outright to a positional heuristic at an identical budget.** Cost is not the reason: a full run is **$2.48**, measured, with zero refusals and zero errors across ~1500 calls. **The reason is that an arm which cannot beat the opening sentences of an abstract is not doing the task the eval was built to measure.** `effort` is settled separately and does hold: `high` differs from `low` by 0.0013 F1 against a measured run-to-run difference of 0.0019, for 49% more output tokens, so `low` is the setting.
- **Alternatives:** (1) Ship the arm as the extractor (rejected — worse than free on every metric, and worse than a four-line positional heuristic). (2) Ship a naive union of both arms (rejected **on arithmetic** — false-positive sets union, so the union inherits at least the arm's 1752 false positives; granting it *every* gold sentence, precision is at most 0.3952 and **F1 at most 0.5666**, below the control's 0.6238. The 127 recoveries its recall gain rests on are *no more than* a rate-matched random selector delivers — ~126 expected, the arm's 127 being the same z = +0.16 recorded above). (3) Record the capability as a scoped-hybrid candidate — **this was the previous version's decision and it is withdrawn**, because its premise was the retracted claim. (4) Conclude that LLMs cannot do this task (**rejected — the evidence does not support it either**; see Consequences).
- **Consequences:** `EVAL_REPORT.md` carries every baseline beside every arm, the retraction and its generalized shape, the miss decomposition, the union bound, the effort pilot, and the reproduction recipe. **⭐ ADR-0013's standing finding is NOT updated, and the earlier claim that it was is withdrawn.** Upstream entity loss remains the dominant, downstream-unrecoverable bottleneck; **nothing here has been shown to reach it.** What is true and required no measurement is structural: `control-real` scores 0 on `endpoint_lost` because it is gated on entity extraction succeeding, so any mechanism not so gated — an LLM, a random baseline, the first four sentences — can touch those sentences at all. **⭐ Conditional revisit — the trigger is a configuration that beats THE BEST FREE BASELINE on `endpoint_lost`, not merely a rate-matched null, and not merely `control-real`'s structural zero.** The previous version set that bar at the rate-matched null, which a future arm could clear while still losing to the first two sentences of an abstract; that would have licensed reopening the question on evidence already known to be insufficient. **Any future arm reporting a restricted-population result must report the baselines beside it** — a bare restricted recall is uninterpretable, and this ADR is the reason. **The bar is now 0.5544** (`first 2` padded to 2274, exact), from the 2026-08-18 sweep above — not the 0.5496 this ADR first published. The family is swept for `first k`, `last k` (k = 1…6) and a proportional ladder, so the "sampled, not swept" caveat is discharged for those. **One member named in the original caveat remains unmeasured and the reason is recorded rather than left as an omission: section-aware.** BC5CDR ships unstructured abstracts, and an uppercase section marker (`RESULTS:`, `METHODS:`, `CONCLUSIONS:`) appears in only **128 of 500** documents — so a section-aware selector degenerates to a positional one on the other 372, and whatever it could win is bounded by a quarter of the corpus. That is a reason to defer it with a number attached, not a reason to call the family complete: **the bar can still only rise, and any future arm must clear whatever the best free baseline is when it runs, not the figure printed here.** **What this does NOT establish:** that an LLM cannot do this task. The system prompt asks for *"sentences that state the study's findings"* while gold encodes *"sentences where both endpoints of an annotated CID relation appear"* — different questions — and `effort` was swept while the prompt was not. This measures **one prompt against one proxy**, and prompt iteration is the obvious cheap next experiment. **⭐ PLACEMENT — why `biolit/extract/llm.py` stays on `master` when ADR-0011's ingest and ADR-0012's fallback linker did not**, recorded because ADR-0013 wrote its own placement note precisely so a future reader would not apply the consumer rule mechanically. Those two were **rejected mechanisms whose only consumer was the measurement that rejected them**, so merging them would have left dead modules. This is different on two counts. First, the module is the *arm under measurement* and `EVAL_REPORT.md`'s reproduction recipe runs it — deleting it makes the headline unreproducible, and this branch has just spent a full correction pass on the principle that a documented number must be re-runnable. Second, it is **not coupled to the rejection**: it takes its client as `Any` and does not import `anthropic`, so `biolit` gains no hard dependency, and Phase 5's Critic needs the same SDK regardless of this verdict. **What is rejected is the arm's use as an extractor, not the seam.** If Phase 5 does not materialise, the consumer rule applies again and this file is the first thing to remove. **Also recorded:** `endpoint_unlocatable` measured **0** and is an empty-but-correct bucket, not a finding; and **321 of 1066 gold CID relations (30.1%) are realized by no gold sentence**, for which cross-sentential assertion is the expected dominant cause but an unannotated endpoint and a gap-positioned endpoint contribute an unmeasured share.

## ADR-0014 — Every operand of a compound condition must be independently exercised by a fixture
- **Date:** 2026-08-11
- **Status:** Accepted — a standing review rule, checked on every task
- **Context:** The same defect shape has now been found **seven times across four phases**, always by review or mutation testing and never by the test suite, which was green in every case. It has three sub-shapes, all of which the same question catches. **(1) A compound condition with only one operand covered:** `40c64de` — `unplaceable_entities`' guard is `start is None or sentence_index(...) is None`, and only the `start=None` half had coverage, so `if entity.start is None:` alone would have passed; and the instance that prompted this ADR, `classify_misses`' `if entity.canonical_id is None or entity.start is None:`, where **neither** disjunct is exercised because no `Entity` fixture in the suite sets either field to `None`. **(2) A two-sided case covered on one side:** `0f41550` — the unlinked-entity guard was exercised on CHEMICAL but not DISEASE; `a030807` — the gold-provenance check tested invention but not omission, and the omission direction turned out to shrink `endpoint_lost` 2→1 with closure still passing; `3259b10` — the `if expected is None: return` guard for untabulated corpus sizes had no test at all. **(3) A value space collapsed so a weaker predicate survives:** `d4786b7` — a scalar-equality mutant `labels.get(id) == {required}` passed all three existing tests because no label map in any of them held a set with more than one member, though 79 real CTD concepts do; `a5ff590` — round 4's `pred`-independence was unpinned because every fixture touching the branch set `pred` to `set()`, so a check over `gold` and a check over `gold - pred` were indistinguishable. Seven instances is not a run of bad luck; it is a blind spot the current process does not close, and each was caught by chance — a reviewer choosing to mutate that particular line.
- **Decision:** **Every compound boolean condition must have each disjunct and each conjunct independently exercised by at least one fixture, and this is a checked item on every task review rather than something a reviewer may or may not think to mutate.** The same review question extends to the two adjacent shapes above: a two-sided case needs both sides, and a predicate over a set, mapping or collection needs at least one fixture whose value distinguishes it from the obvious weaker predicate (a multi-member set where a scalar comparison would otherwise pass; a non-empty operand where an empty one makes two expressions coincide). The operational test is a mutation: if replacing the condition with either operand alone leaves **every gate** green, the condition is unpinned and the task is not done. **The enforcing gate is sometimes `pyright` rather than `pytest`, and that counts as pinned.** Task 6b established the first instance: `classify_misses`' `canonical_id is None` disjunct cannot change any bucket outcome, because the id sets it guards hold only non-`None` MeSH strings that a `None` can never match — the mutant survived the full suite and agreed with the original in **4000 of 4000** randomised differential trials — yet dropping it makes `per_sentence` infer `set[str | None]` and pyright fails with two errors. Its value is type integrity, so the correct record is the verbatim pyright output; writing a pytest case for it would produce exactly the test-that-cannot-fail this ADR's last clause forbids. **STANDING PRINCIPLE for step (a), applied whenever reachability is contested rather than obvious — in particular when an operand is unreachable by type but the type could later be widened: ask whether, IF the guarantee were weakened, the guard's presence would make the resulting failure LOUDER or QUIETER.** A guard whose only effect under weakening is a silent `continue`, a swallowed branch, or a quietly-empty return is **worse than its absence** and should be deleted regardless of which kind of unreachability it rests on — it converts a crash that names the offending input into a wrong answer that names nothing. Decide this by running the weakened case, not by reasoning about it; the worked example in Consequences reversed the intuition when measured. **Where the honest answer is that removal would ALSO be silent, this principle does not decide, and neither does the type/runtime distinction — that case is open and is to be flagged as such rather than resolved by analogy to this one.**
- **Alternatives:** (1) Rely on branch coverage tooling (rejected — branch coverage is satisfied by taking each *branch*, not by distinguishing each *operand*; every one of the seven instances above would report as covered, since the branch was always taken by some fixture). (2) Leave it to reviewer judgment, the status quo (rejected — that is precisely what produced seven instances; it worked each time only because a reviewer happened to mutate the right line, which is not a process). (3) Require a fixture per operand only for conditions in eval-harness code (rejected — `40c64de` and `0f41550` are in `biolit/cluster/` and `biolit/extract/`, production packages, so scoping the rule to the harness would have caught neither).
- **Consequences:** Added to the Phase 4 plan's Global Constraints, so the remaining Task 7–9 dispatches inherit it, and carried in every implementer and reviewer brief from here. Task 6b applies it to `classify_misses`' `canonical_id is None or entity.start is None` — the seventh instance and the one that prompted this. **The rule is about pinning, not about adding tests for their own sake:** where a mutant is *provably* equivalent the correct handling is still to flag it, not to write a hollow test and not to delete the guard — Task 6's final round identified three such (`elif entity.label is EntityLabel.DISEASE` versus a bare `else`; `sorted(missed)` iteration order; and `mention.label not in by_label`, **which the final review later reclassified — see the next paragraph — and which has since been deleted**). A rule that cannot distinguish an unpinned condition from an unkillable one would just manufacture noise. **Task 7 added a third category, and it is checked FIRST because it dissolves the question rather than answering it: an operand that is provably UNREACHABLE needs neither a fixture nor a flag.** The plan's `LlmExtractor` guarded `if not spans or not text.strip()`, but `sentence_spans` ends `return spans or [(0, len(text))]` (`biolit/ner/windowing.py:35`), so it cannot return an empty list and `not spans` can never fire. Unreachable code has nothing left to protect — flagging it would tell a future reader to preserve a guard that does nothing, and testing it is impossible by construction. It was deleted, and the implementation now contains no compound boolean condition at all. **So the triage runs: is the operand reachable? If no, delete it. If yes, does removing it turn some gate red? If yes, it is pinned — record which gate. If no, it is provably equivalent — flag it, and neither test nor delete.** Reaching for a test or a flag before establishing reachability is how a dead branch acquires a permanent hollow guard. **The final review then produced the second worked example and the tie-breaker the triage was missing.** `_gold_pairs_by_sentence`'s `mention.label not in by_label` — listed above under "provably equivalent" when the rule was still two-way — is unreachable on **both** available grounds: *by type* (`EntityLabel` is a two-member `StrEnum`, `GoldMention.label` is typed to it, and `by_label` is built literally with exactly those two keys) and *by runtime construction* (both `GoldMention` construction sites take their label from `canonical_label`, whose codomain is those two members or `None`, and `None` never reaches the constructor). **The two kinds are worth distinguishing** — a type-level guarantee can be widened by a future edit in a way that `sentence_spans`' `return spans or [(0, len(text))]` cannot silently change — **but "keep it when the guarantee is type-level" is the wrong tie-breaker, and measurement showed why.** Fed a mention whose label has no `by_label` key, simulating exactly the future widening the worry is about: **with** the guard, `_gold_pairs_by_sentence` returns `{}` and the gold sentence silently disappears, detectable only by the 500-document regression pin and never by a `--limit` pilot; **without** it, a `KeyError` fires at the offending mention. **The guard makes the failure it supposedly protects against quieter, not louder.** So the tie-breaker is: *if the guarantee were later weakened, does the guard's presence make the failure louder or quieter?* A guard whose only effect under weakening is a silent `continue` is worse than its absence and should be deleted regardless of which kind of unreachability it rests on — which is what happened here. **This instance does not settle the harder case**, an operand unreachable only by type whose absence would itself be silent; that remains open, and a future reviewer meeting one should reason from the louder/quieter test rather than assume this precedent covers it.

## ADR-0013 — Chemical–disease relation extraction does not get its own phase: same-sentence pairing captures 77% of a ceiling that upstream entity loss already caps
- **Date:** 2026-07-29
- **Status:** Accepted — **conditionally revisitable** (see Consequences)
- **Context:** ADR-0008 defines a cluster as papers about the same chemical–disease relationship, but nothing in the pipeline decides which chemical pairs with which disease inside a paper. The cheapest answer is the full cross product of linked chemicals × linked diseases, which is obviously lossy on precision; the open question was **how lossy, and whether closing the gap requires a real CID relation extractor** with a model, a training set and its own phase. That question was answerable without assumption because **`CDR_Data.zip` ships gold CID relations** — 4-field `PMID/CID/chemMeSH/disMeSH` records that the 6-field mention parser had been silently skipping since Phase 2. (An earlier note in this project asserted BC5CDR "does not label which papers belong together." That was wrong; it was corrected and verified against the real corpus before any of this work proceeded.) Two arms were measured: **Arm A** synthesizes entities from gold mentions + gold ids over all **1500** documents; **Arm B** runs the real NER + linking pipeline, held out to **Test-500** because the NER checkpoint was fine-tuned on BC5CDR's training split — a correctness requirement, not a sample-size preference. Scoring is at three levels, with **paper-pair primary**, because `ContradictionFinding` is `(paper_id_a, paper_id_b, label, rationale)` and a pair is the Critic's unit of work.
- **Decision:** **Do not scope CID relation extraction as a phase. `SameSentencePairing` is the pairing strategy of record.** Same-sentence co-occurrence beats the cross product on **every arm and every metric level** — paper-pair F1 **0.4305 → 0.6204** on gold entities/1500 and **0.5484 → 0.6327** on the real pipeline/500 — and roughly **halves the Critic's workload**, with distinct Critic calls dropping 7066 → 3571 on Arm A (1.98×) and 460 → 279 on Arm B (1.65×), a direct cost result since every call becomes an LLM invocation in Phase 5. The rejection of relation extraction rests on three reasons, in order of weight: **(1) the binding constraint is upstream, not in pairing** — of 1066 gold CID relations in Test-500, **430 (40.3%) have an endpoint the real NER + linking pipeline never produced for that paper**, and no pairing mechanism, heuristic or learned or perfect, pairs an entity that was never extracted; **(2) the free heuristic already captures 77.0% of a precision-perfect ceiling at zero model cost** — an oracle granted perfect pairing over Arm B's *real* entity set scores F1 **0.8212** against same-sentence's **0.6327**, so the entire pairing-strategy question is worth at most **+0.1886 F1** and three quarters of it is already taken by one sentence-boundary lookup; **(3) the realistic win is smaller than +0.1886**, because part of same-sentence's recall is *accidental* co-clustering through wrong shared keys, which a precision-oriented extractor would give up.
- **The entity-conditioned oracle is precision-perfect and recall-capped, NOT a hard F1 bound.** Stated explicitly because the same class of error was made and corrected inside this very sub-project. The oracle's precision is **1.0000 by construction** — it emits only gold-true keys — so it bounds recall and nothing else. The **empirical proof, not merely the structural argument**: same-sentence's paper-pair recall is **0.7346, which exceeds the oracle's 0.6967.** A mechanism already measured beats the "ceiling" on recall, because paper-pair recall credits a co-clustered pair whenever two papers share *any* predicted key, so a **wrong** key held by both papers can accidentally co-cluster a genuinely gold-related pair — a win the oracle forgoes. A mechanism trading precision for recall can therefore exceed F1 0.8212. **The 77.0% figure is a fraction of a one-sided construction and must always be cited as such.**
- **The spec's original "Arm A is a ceiling for Arm B" claim was false, and is kept with its refutation rather than edited away.** The arms run on different corpora (1500 vs 500) and were never directly comparable; made apples-to-apples they **invert** — Arm A restricted to Test-500 scores same-sentence P 0.4279 / R 0.9005 / **F1 0.5802**, *below* the real pipeline's P 0.5556 / R 0.7346 / **F1 0.6327**. Granting perfect entities can only *add* candidate pairs, and adding candidates against a fixed gold pair set can only cost precision. The reusable rule: **any construction that improves recall by granting something correct, without touching what the system emits wrongly, is a ceiling for recall alone — before calling anything a ceiling, ask what it can make WORSE.** A corollary finding is that NER + linking act as an unintended **precision filter** (the entities they resolve are the more canonical ones, likelier to carry an annotated relation) — a property of **this corpus and this gold standard**, and emphatically **not** an argument that noisier extraction is better or that better NER is unnecessary. The 40.3% endpoint loss above is the direct measure of what better NER would buy.
- **Alternatives:** (1) Build a CID relation extractor as Phase 3D (rejected — it competes for at most +0.1886 F1, realistically less, on the 59.7% of relations whose endpoints survive extraction, and the standing rule is no infrastructure without a demonstrated consumer; there is no Critic yet). (2) Ship the cross product and let the Critic filter (rejected — it costs 0.1899 F1 on Arm A and roughly doubles the Critic's call count, i.e. doubling LLM spend to recover precision a free heuristic already has). (3) Redefine the cluster key as a single concept rather than a chemical–disease pair (rejected outright at the design stage — single-concept keys do not solve the pairing problem, they redefine clustering into something that no longer serves the reason it exists per ADR-0008; that is abandoning the goal, not simplifying it). (4) Loosen same-sentence to same-paragraph or an N-token window (not measured, not rejected — a cheap sweep, but the headroom above caps what any pairing tweak can win).
- **Interpretation caveat on the precision figures — and what it does not license:** gold CID is **narrower than co-mention**, since BC5CDR annotates a chemical–disease pair only where the abstract asserts causal induction, so some pairs scored false-positive are genuine co-mentions that simply are not CID relations. That corrects **how the precision number should be read**; it does **not** make low precision matter less practically. The Critic's actual task — judging whether two papers contradict each other about a drug–disease effect — *is* the narrow, causal-relation-shaped task BC5CDR annotates, and a co-mention that is not a CID relation is still a wasted Critic call.
- **Placement — why `biolit/cluster/` is in the production package despite having no production caller yet.** It currently has exactly one non-test consumer, the eval itself, which on its face engages the standing "no infrastructure without a demonstrated consumer" rule that kept ADR-0011's ingest and ADR-0012's fallback linker on unmerged branches. **The rule's real discriminator is whether the module's value was contingent on the measurement's outcome.** For the fallback linker it was: the measurement rejected it, so the module was worthless. Here it is the opposite — the measurement's outcome is that same-sentence pairing **wins**, making `biolit/cluster/` the accepted Phase 3 implementation; `Cluster` and `PipelineState.clusters` have been domain types since Phase 1, so the interface was designed rather than invented for this eval; and the package is ~175 lines of pure stdlib adding no dependency, artifact or model. Decisively, moving it under `biolit_evals/` would break this eval's stated premise that **both arms run the production code path** rather than a parallel gold-only implementation — which is ADR-0010's argument verbatim (the eval exists to measure the production path). **The genuine gap is wiring, not location: nothing populates `PipelineState.clusters` yet.** This note exists so a future reader applying the consumer rule mechanically does not delete a module the measurement said to ship.
- **Consequences:** `EVAL_REPORT.md` carries the three-level tables, the corrected ceiling analysis, the entity-conditioned oracle, all three anchor definitions and the reproduction recipe, so the result stands without the code. **Three harness anchors gate every run on the real path**, not merely in tests: `assert_key_recall_anchor` requires `cross_product` key recall to round to exactly 1.0000 on gold entities (the cross product emits every combination by construction, so a miss means the harness lost gold); `assert_gold_cluster_anchor` requires gold cluster counts of 500→80 and 1500→325, a **loader-correctness check on `load_bc5cdr_cid_relations`, explicitly not a clustering-quality check**; and `assert_full_reachability_on_gold_entities` requires the oracle to reach **every** gold relation on Arm A, since a gold relation's endpoints are themselves gold mentions — which gates the ceiling the decision rests on. A fourth guard, `assert_dataset_size`, halts any run whose corpus size contradicts its `dataset` tag, closing a hole where an Arm B run over anything but exactly 500 documents was scored and logged with no anchor firing at all. **Cluster-size capping is carried forward as a design consideration, not built:** `top5_pair_share` reaches **0.503** on Arm B same-sentence — half of all cluster comparisons come from five clusters, the largest contributing 55 (11 papers), and 378 from one 28-paper cluster on Arm A — so a cap is clearly motivated, but there is no Critic to protect and building it now would violate the same rule this ADR applies to relation extraction. The measurement that motivates it is committed and waiting. **Conditional revisit:** reopen if the Critic, once built, shows measurable harm traceable to same-sentence's false pairs specifically — as distinct from the 40.3% lost upstream, which relation extraction cannot address. Alternative #4 was never measured, so the 77.0% figure prices *same-sentence*, not the best achievable heuristic.
- **⭐ Standing project-level finding — this is the second time upstream entity loss has been the dominant, downstream-unrecoverable bottleneck.** It is named here rather than left implicit across two ADRs. In **Phase 3C** the mechanisms that looked like the answer were fragment merging and then an embedding fallback linker; measurement showed the dominant loss was **1679 gold mentions whose span NER got exactly right but which linked to nothing**, priced at **+0.0821 concept F1 — 39× the fragment-merge ablation and the largest recoverable loss measured anywhere in this project** — of which the fallback then realized only **24%**, at 53.9% mention precision (ADR-0012). In **Phase 3 clustering** the mechanism that looked like the answer was a CID relation extractor; measurement showed **40.3% of gold relations lose an endpoint before pairing is ever consulted**. Both times the loss was **downstream-unrecoverable**: no linker fixes a span NER missed, and no pairing strategy pairs an entity that does not exist. Two instances of one finding, not two coincidences. **The operative consequence: entity recall — NER coverage and linking coverage — is this pipeline's dominant constraint, and downstream reasoning components must be priced against an entity-conditioned ceiling rather than an oracle-entity one, or they will be scoped against headroom that does not exist.** The entity-conditioned oracle here is the concrete template, and it should be the default construction for pricing Phase 4 and Phase 5 components.

## ADR-0012 — The embedding fallback linker is documented, not shipped: a real effect, too weak and too costly to justify now
- **Date:** 2026-07-28
- **Status:** Accepted — **conditionally revisitable** (see Consequences)
- **Context:** ADR-0011 redirected the alias-gap question to a genuine generalization sub-problem, and the ceiling split showed **paraphrase is ~99% of the +0.0821 oracle ceiling**. That ceiling is **recall-only by construction** (granting gold ids converts `fn`→`tp` and cannot add a false positive, which is why `fp` stayed pinned at 312 across all four oracle variants), so its distance from reality was unmeasured. The open question was not "is there a gap" but **"what does a real linker cost in precision to close any of it."** Measured over the **full 3209-mention NIL population** — not the favorable 1136-mention paraphrase slice — because a real linker cannot see gold alignment and fires on all 3209, and because a slice-scoped figure would be silent about exactly the false positives the system would pay.
- **Decision:** **Do not ship the embedding fallback, and do not merge the branch that measured it.** The effect is **real and correctly attributed** — this is explicitly *not* a repeat of ADR-0011's null. SapBERT (`cambridgeltl/SapBERT-from-PubMedBERT-fulltext`, all 552,756 alias rows, exact chunked cosine, breakpoint-exact threshold sweep) peaks at **F1 0.7897 (+0.0200)** against the 0.7697 dictionary baseline, and beats the character n-gram TF-IDF control **3.4×** (+0.0200 vs +0.0058). That control existed so a gain could not be credited to a model until plain fuzzy string matching was ruled out; it was not ruled in. **The mechanism is semantic generalization, not string similarity, and those are materially different builds.** The rejection is on **cost and fragility relative to value**, and rests on three numbers rather than the ΔF1: **(1) mention-level precision at the peak is 53.9%** (365 correct of 677 fired) — every second link is wrong; **(2) `mentions_wrong / Δfp` is 2.89** (312 wrong mention links cost only 108 *new* false positives), so the positive F1 delta exists only because document-level set semantics absorb ~2.9 wrong links per error the metric reports; **(3) realized gain is 24% of the oracle ceiling** (+0.0200 of +0.0821). Against that, shipping costs an ~849 MB fp16 index, a second BERT forward pass in the linking path, and a threshold that must be tuned — and at threshold 0 the mechanism scores **F1 0.7027, actively worse than not firing at all.** Label-constraining the candidates helps by +0.0017 and is free, so it is the right configuration if this is ever built.
- **Scope — this is a clustering verdict, not a pipeline verdict:** measured entirely against **document-level concept-set scoring**, the metric clustering consumes. It mirrors the abbreviation-expansion caveat (ADR-0011 consequences) **in the opposite direction**: there a mechanism looked worthless at concept level while genuinely correcting 543 mentions, so mention-level consumers were told not to inherit the rejection. Here the absorption that *rescues* the number for clustering is exactly what a mention-level consumer does not get. **Phase 4 (evidence attribution) and Phase 5 (contradiction detection) must not inherit this conclusion in either direction** — for them the statement is stronger and more negative: a concept id that is wrong roughly half the time is **unusable as ground truth for a specific claim**, and would need a much higher threshold (trading away most of the recall) or a better model first. Both should re-measure against their own metric.
- **Alternatives:** (1) Ship it at the argmax-F1 threshold (rejected — +0.0200 bought at 53.9% mention precision, on a metric that demonstrably hides 2.9× the error it reports; the standing rule is no infrastructure without a demonstrated consumer, and a mechanism whose value depends on the metric not seeing its mistakes is a weak consumer). (2) Ship the TF-IDF control instead, as the cheap non-neural option (rejected — +0.0058 is not worth a second index either, and it answers the wrong question: the control's job was attribution, not deployment). (3) Report the paraphrase-slice figure as the headline, where the same mechanism looks better at +0.0254 and 69.0% mention precision (rejected outright — **70.2% of the wrong links land on the 1530 non-gold-aligned NILs the slice cannot see**, and the slice overstates the full-population gain by 27% relative; this is the fourth instance of a favorably-selected population reporting a better number than the system would pay, after 91→11, 543→4, and 1136→431). (4) Improve the policy before deciding — per-label thresholds, margin-based abstention, calibration (deferred, not rejected: see Consequences).
- **Consequences:** The implementation stays on the unmerged branch **`phase-3c-fallback-measurement`** (`0f4eac7`..`fbcae08`), so `master` carries no dead module while the experiment stays recoverable — the same handling as `phase-3c-mesh-alias-enrichment`. The `EVAL_REPORT.md` section carries the full curve, both anchor validations, the reproduction recipe, and the two anomalies that were chased down, so the result is reproducible without the code. **Conditional revisit — this is deferred, not closed.** Reopen if **clustering later shows measurable harm traceable to the missing paraphrase-linked concepts** (the concrete trigger, mirroring ADR-0011's conditional framing), or if a stronger policy is worth pricing: alternative #4 above was never measured, so the 24%-of-ceiling figure prices *top-1 with one global threshold*, not the best achievable embedding fallback. **The concept→label map stays on the branch too**, and does not get quietly promoted: it is built from the same CTD download as the alias table in the same run (**0 orphans**, verified rather than assumed; **79 multi-label concepts**, the empirical justification for `dict[str, set[EntityLabel]]` over a last-write-wins scalar, which would have silently mislabeled all 79). It is well-tested and independently useful, but its only consumer is the rejected fallback, so promoting it would violate the same rule this ADR is applying. If a consumer appears, it is the cheapest piece of this branch to extract.

## ADR-0011 — Dictionary enrichment from MeSH is rejected: the alias gap is not an alias-coverage gap
- **Date:** 2026-07-25
- **Status:** Accepted
- **Context:** The exact-span link audit found **1679 gold mentions whose span NER got exactly right but which linked to nothing**, and the oracle ceiling priced that population at **+0.0821 concept F1** — 39× the fragment-merge ablation, and the largest recoverable loss measured anywhere in this project. Reasoning from the structural fact that *every one of those mentions has a MeSH concept by definition* (the gold assigns one), I concluded the gap was **alias coverage**: fixable by a richer, still-deterministic dictionary, with no model. That inference was explicit in `EVAL_REPORT.md`, and it drove the decision to test MeSH's own entry terms before scoping any embedding fallback.
- **Decision:** **Reject dictionary enrichment from MeSH, and do not merge the ingest that tested it.** MeSH `desc2026` + `supp2026` entry terms were ingested (streamed via `iterparse`; descriptor tree numbers under `C*`, `F03*`, `D*`; supplemental records of `SCRClass` 1 and 3 — note the real attribute is **`SCRClass`**, not `SupplementalRecordType`) and unioned with the CTD table. Measured model-free over all 9718 linkable BC5CDR gold mentions, it rescues **3 of the 2514 CTD-NIL surfaces (0.1%)** and breaks **0** previously-correct links. The cause is arithmetic: CTD contributes 551,669 aliases, MeSH 784,332, and their union only **819,422** — an overlap of ~517k, because **CTD's `MESHSynonyms` column already *is* MeSH's entry terms**. Enriching CTD from MeSH re-adds what CTD already had.
- **The correction this forces — "the concept exists" ≠ "the surface exists":** the inference above is **wrong**, and is kept in the report with a pointer to its refutation rather than edited away. A concept being present in MeSH does not imply a fuller alias list reaches it, because the missing surfaces are not absent synonyms. Validated as a genuine null and not a broken parse: the ingest yields **271,668 distinct concept ids**, and for **2448 of the 2510** surfaces that remain NIL the gold concept **is present** — only the surface is missing (62, or 2.5%, are genuinely absent, mostly outside the kept trees, e.g. `blood urea nitrogen`). Classifying the 2510: deterministic normalization **50 (2.0%)**, abbreviation-shaped **1024 (40.8%)**, paraphrase/other **1436 (57.2%)** — `TdP` → *Torsades de Pointes*, `NO` → *Nitric Oxide*, `cognitive deficits` → *Cognition Disorders*, `hepatic injury` → *Chemical and Drug Induced Liver Injury*. No controlled vocabulary enumerates author abbreviations or paraphrases, which is exactly why more vocabulary changed nothing.
- **Alternatives:** (1) Merge the ingest anyway, as a harmless superset (rejected — it adds a 62 MB download, a second artifact source and a streaming XML parser to production for a measured 0.1% gain; this project's standing rule is no infrastructure without a demonstrated consumer, and a falsified hypothesis is not one). (2) Try UMLS instead (rejected for now — UMLS is licence-gated, and the failure mode here is not vocabulary size but surface form; the same overlap argument applies to any controlled vocabulary). (3) Loosen the tree/class scope filter to recover the 62 absent concepts (rejected — 2.5% of a population whose overall rescue rate is 0.1%, and loosening it admits anatomy/organism surfaces a CHEMICAL/DISEASE linker can match wrongly).
- **Consequences:** The implementation is kept on the unmerged branch **`phase-3c-mesh-alias-enrichment`** (commits `a246703`, `5e2d3d5`), so master carries no dead module while the experiment stays recoverable; this ADR plus the EVAL_REPORT section carry enough detail (sources, filters, counts, validation) to reproduce the result without it. The finding **redirects rather than closes** the question: the gap splits into a deterministic sub-problem (**abbreviations, ~41%+ — addressable by in-document expansion, since these abstracts define abbreviations on first use**) and a genuine generalization sub-problem (**paraphrase, ~57%**). Only the second is embedding territory, so the fallback's addressable share is materially smaller than the +0.0821 ceiling implies. Sizing that split is the prerequisite for scoping a fallback at all.

## ADR-0010 — Long documents are windowed inside the NER layer, not by callers
- **Date:** 2026-07-24
- **Status:** Accepted
- **Context:** The first full-scale end-to-end eval run crashed with `RuntimeError: The size of tensor a (549) must match the size of tensor b (512)`. The NER checkpoint's tokenizer declares no `model_max_length`, so it never truncates, while BERT-family position embeddings cap input at 512 tokens. **11 of the 500 BC5CDR test abstracts (2.2%) exceed that** (median 267, max 722). It had never surfaced because every prior measurement — Phase 2 NER, Phase 3A linking, the domain sample — ran on *sentences*. Phase 4's Extractor feeds whole abstracts, so this would have crashed on roughly 2% of real papers in production. This decision was made during Phase 3B execution and is **not** in that phase's plan, which is why it is recorded here.
- **Decision:** Window inside `NerModel`, so `extract_entities` is safe on text of any length and every consumer inherits the fix without changing a call site. The alternative — windowing in the eval's `predict` function — was rejected outright: the eval exists to measure the production path, so fixing it only in the eval would have made the report claim success against a code path production does not run. Windows are packed from **whole sentences** (an entity practically never spans a sentence boundary, making it the safest cut point); consecutive windows **overlap by one sentence**; offsets are shifted back into document coordinates; and results are de-duplicated, with any span strictly contained in another span of the same label dropped, because overlapping windows can otherwise emit nested spans that cannot occur on single-window input.
- **Alternatives:** (1) Truncate to 512 tokens (rejected — silently discards entities in the tail, and the discarded region is exactly where conclusions live). (2) Exclude over-long documents from the eval (rejected — biases the corpus toward shorter abstracts and leaves the production crash live). (3) Rely on the HF pipeline's own chunking (rejected — token-classification pipelines do not window automatically, which is precisely why the raw tensor reached the model).
- **Consequences:** `extract_entities` handles arbitrary-length text, and end-to-end numbers on long documents are therefore not directly comparable to Phase 2's sentence-level NER F1. **Two known limits, recorded rather than hidden:** (a) the one-sentence overlap only materializes when a window holds more than one sentence — a single sentence filling an entire window has hard-cut boundaries; at the 450-token budget against normal sentences every internal boundary is spanned, but the guarantee is conditional, not universal. (b) A whitespace-free run longer than the budget is split at character granularity, which can cut an entity, because the alternative is losing the whole document to a tensor-size error. Both are pinned by tests, including a paired test showing the overlap guarantee genuinely fails when overlap is disabled.

## ADR-0009 — A merged fragment candidate may only fill a NIL gap, never overwrite a link
- **Date:** 2026-07-23
- **Status:** Accepted
- **Context:** `canonicalize()` originally applied a merged fragment candidate **unconditionally** to every entity it spanned (the "merged candidate first, first hit wins" ordering written into the canonicalization spec §4). That ordering is unsafe because `merge_fragments` is deliberately permissive: a connector-joined run of adjacent same-label spans merges when **any** token is "fragment-shaped" (all-caps, contains a digit, or is under three characters). Real clinical notation satisfies that trivially — `ASA/clopidogrel`, `HTN/DM`, and `vitamin D-calcium` all merge, alongside the desirable `TMP-SMX`. Combined with unconditional application, a spurious merge that happened to resolve to a real alias would assign **one wrong shared MeSH ID to several entities that each linked correctly on their own**. This is the worst failure mode available in this layer: it is silent (nothing errors), it corrupts multiple entities at once, and it does so at exactly the seam clustering keys on — so it would surface as papers wrongly clustered *together*, the mirror image of the ADR-0008 failure. It was caught by whole-branch review rather than by tests: the "adversarial must-not-merge" test used `aspirin-warfarin`, where *neither* token is fragment-shaped, so it never exercised the permissive branch it was written to guard.
- **Decision:** `canonicalize()` looks up **every entity on its own surface first**. A merged candidate's concept is then applied **only to constituents whose individual lookup returned NIL**. A merge can fill a gap; it can never overwrite a link. A regression test pins this: two individually-linkable entities keep their own concepts even when their merged surface also resolves (verified failing against the previous implementation — both entities took the merged concept — and passing after).
- **Alternatives:** (1) Tighten `merge_fragments` so it cannot propose these runs (rejected *as the primary fix* — it trades one hand-tuned heuristic for another and cannot be validated without data; deliberately deferred until the merge-path eval shows where the rule is actually too permissive). (2) Keep merge-first and accept the risk (rejected — silent, multi-entity, and located at the clustering seam). (3) Require a merged candidate to outrank individual links by confidence (rejected — the dictionary linker returns no confidence score, so there is nothing to rank on).
- **Consequences:** The ADR-0008 motivating case is unaffected: `GLP` and `1RA` are each NIL alone, so the merged concept still applies to both. The permissive heuristic's blast radius is now bounded to NIL gaps, which is *why* tightening it is deferred rather than urgent. **Caveat:** the reported linking metrics do not exercise this path at all — the scorer calls `Linker.link()` on gold surfaces and never calls `canonicalize()` — so this ordering is currently guaranteed by unit tests only. Measuring it is the merge-path eval, which is scoped ahead of clustering precisely because some current NIL cases may be recoverable by better merge behavior before any fallback linker is justified.

## ADR-0008 — Entity canonicalization is a Phase 3 prerequisite, not a clustering subtask
- **Date:** 2026-07-22
- **Status:** Accepted (decision to prioritize; design deferred to Phase 3)
- **Context:** Phase 2's domain error analysis (`biolit_evals.error_analysis --dataset domain`, transcript in `docs/EVAL_REPORT.md` "Interpreting the gap") found that of 57 errors on the domain sample, **34 (60%) are boundary disagreements on entities the model did detect** — not failures to find an entity. The dominant pattern is drug-class abbreviations and hyphenated compound names fragmenting under the subword tokenizer, which `aggregation_strategy="simple"` does not reassemble: gold `CFD` predicted as `CF` (×10 in the sample), `GLP-1RAs` split into `GLP` + `1RA`, `SGLT2is`/`DPP4is` partially spanned, `sodium-glucose cotransporter-2 inhibitors` truncated to `sodium-glucose`. Crucially, **this fragmentation is invisible as an NER error to any downstream phase.** Phase 3 clusters papers by shared entities and Phase 5 detects contradictions within those clusters; if `GLP-1RAs` fragments into `GLP` and `1RA` *inconsistently across papers*, entity-keyed clustering silently splits papers that belong together. The failure surfaces as **missing clusters** — an absence — not as a flagged mismatch anywhere. A green NER metric and a plausible cluster count can coexist with this defect. (An unknown share of the 0.81→0.66 headline-vs-domain gap is a tokenization-format confound rather than model weakness — see the eval report — but that caveat does not weaken this finding: the fragmentation pattern is real in the predictions regardless of how much of the *score* gap it explains, and it is the fragmentation, not the score, that breaks clustering.)
- **Decision:** Treat entity canonicalization (mapping surface variants and fragmented spans to a stable normalized key) as a **prerequisite that must exist before entity-keyed clustering is trusted**, not as a refinement layered on afterward. Scope it as its **own brainstorm → spec → decision trail in Phase 3, separate from retrieval/clustering design** — it is a distinct problem (string/ontology normalization) and consequential enough to earn its own decisions rather than being folded in as a clustering implementation detail. This ADR records *why* and *that* it is prioritized; it deliberately does **not** commit to a *how*. The eventual mechanism — abbreviation-aware span merging, dictionary/ontology linking (e.g. MeSH/UMLS), learned normalization, or some combination — is a Phase 3 decision to be made against real clustering behavior.
- **Alternatives:** (1) Fold normalization into clustering as a sub-step (rejected — its design tradeoffs, e.g. ontology dependence and normalization aggressiveness, deserve their own decision trail; burying them makes the clustering ADR do two jobs and hides the tradeoff). (2) Defer normalization until a visible clustering failure forces it (rejected — the failure mode is an *absence* of clusters, which is exactly the kind of silent wrongness the eval work has repeatedly shown does not announce itself; waiting means shipping a plausible-looking but wrong clustering and hoping to notice). (3) Rely on a stricter `aggregation_strategy` or a different checkpoint to stop fragmenting (rejected as *the* answer — may reduce fragmentation but cannot guarantee cross-paper consistency of the surviving surface forms, which is the actual clustering requirement; still worth evaluating as one input to the Phase 3 design).
- **Consequences:** Phase 3 carries an explicit, separately-tracked canonicalization workstream ahead of clustering, with its own spec and ADR. The domain gold sample is intentionally **not** broadened yet (see project notes): a broader domain eval set will be re-derived *after* canonicalization exists, so the annotation effort is spent once against the normalized pipeline rather than twice — mirroring how the ADR-0007 abstract-truncation fix already forced one re-annotation. The `Entity.label` field was tightened to the `EntityLabel` `StrEnum` (applying ADR-0005) as a first, mechanical step toward type-checking entity attributes at the Phase 4 seam; normalization will add a canonical-key/identifier axis to `Entity` in Phase 3, and that shape is deferred to its brainstorm.

## ADR-0007 — Structured abstracts are concatenated with section labels
- **Date:** 2026-07-22
- **Status:** Accepted
- **Context:** `PubMedClient` parsed abstracts with `article.findtext(".//Abstract/AbstractText")`, which returns only the *first* matching element. PubMed structured abstracts carry one `<AbstractText>` per section, so we silently kept only the opening section. Verified live on PMID 27295427 (LEADER trial): 156 of 2259 characters — 7% — with METHODS, RESULTS, and CONCLUSIONS discarded. Phase 1's tests all passed because every committed cassette happened to contain an unstructured abstract; the bug surfaced only when a human-facing task read real pulled text. This is severe for this project specifically: the system exists to extract findings and detect contradictions, and those claims live in RESULTS/CONCLUSIONS.
- **Decision:** Concatenate all `<AbstractText>` elements in document order. Use `"".join(el.itertext())` per element so nested inline markup (`<i>`, `<sup>`) is preserved rather than truncating the section at its first child tag. When an element carries a `Label`, prefix that section `"<LABEL>: "` — this is how PubMed itself renders structured abstracts, so it stays faithful to the source and preserves section structure for downstream extraction. Join sections with `"\n"`. Unstructured abstracts and absent abstracts keep their existing behavior exactly (plain text; `None`).
- **Alternatives:** join section texts without labels (rejected — discards structure that the Extractor and contradiction phases can use, and PubMed renders the labels anyway); keep a list of sections on `Paper` (rejected for now — changes the Phase 1 model contract and no consumer needs per-section access yet; revisit if one does).
- **Consequences:** Abstract text is complete. **Caveat:** because the `"LABEL: "` prefixes are synthesized, character offsets into `Paper.abstract` no longer index any contiguous string in the source document. For a citation-backed system that quotes excerpts, any future offset-based quoting into an abstract must account for this — prefer quoting the section text, not raw offsets. The Phase 2 domain gold sample was rebuilt from post-fix abstracts; the pre-fix sample was discarded rather than patched.

## ADR-0006 — Domain-sample NER annotation is blind and from-scratch
- **Date:** 2026-07-21
- **Status:** Accepted
- **Context:** Phase 2's hand-annotated domain sample exists to test the NER model *independently* of the BC5CDR benchmark — specifically to surface where the model fails on our own corpus. A model-assisted "pre-label then human-verify" workflow is faster but introduces anchoring bias: annotators are measurably worse at catching false negatives (entities the model missed) when reviewing a pre-populated candidate list than when reading cold. That false-negative blindness is exactly the failure mode the sample is meant to catch.
- **Decision:** Annotate `evals/gold/domain_sample.jsonl` blind and from scratch — reading raw abstract sentences with no model predictions visible. Finalize the gold file first, then run the model and score. Any comparison of model-influenced labeling is a separate, clearly-labeled secondary artifact, never a substitute for the blind pass. Record source PMIDs/paper ids as provenance on every annotated sentence. Document both the single-annotator limitation and this methodology in the eval report.
- **Alternatives:** model-assisted annotation then human review (rejected — undermines the sample's sole purpose by biasing it toward the model's own recall gaps); benchmark-only eval (rejected earlier — loses the "works on my actual corpus" signal).
- **Consequences:** More annotation effort, but the domain F1 is an honest independent check. Provenance keeps the sample traceable if papers are re-pulled. The unbiased headline number remains the BC5CDR test split; the domain sample is a supporting cross-check.

## ADR-0005 — String-valued enums use `enum.StrEnum`
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** The Phase 1 plan wrote enums as `class X(str, Enum)`, but the project's ruff ruleset includes `UP`, whose `UP042` rule flags that pattern and fails the required lint gate. The plan mandated both the pattern and a green gate — a conflict surfaced during Task 2.
- **Decision:** All string-valued enums inherit from `enum.StrEnum` (Python 3.12). Behavior is identical for pydantic JSON serialization and `is`/`==` comparisons; the full `UP` ruleset stays active rather than suppressing a valid rule.
- **Alternatives:** keep `(str, Enum)` and add `UP042` to ruff `ignore` (rejected — silences a legitimate modernization rule to preserve example code).
- **Consequences:** `Source`, `TextType`, `LicenseTier` (Task 2) and `ContradictionLabel` (Task 3) use `StrEnum`. Applies to all future enums.

## ADR-0004 — Full-text signalling: three-state `text_type` + separate license axis
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** A paper's full text may *exist* yet not be *reachable yet* (bioRxiv `jatsxml` URL can 404 for freshly-posted preprints; PMC membership is not a fetch), and *existence* is independent of *permission to extract/display* (verified live: a medRxiv record with a full `jatsxml` path but `license: cc_no`). A boolean `full_text: bool` conflates all three concerns and would silently over-promise to the Synthesis agent.
- **Decision:** Model two independent axes. (1) `text_type` enum with three states — `full_text_available` (exists AND verified reachable), `full_text_unverified` (pointer exists, unconfirmed), `abstract_only`. Ingest never yields `full_text_available`; a later verification/fetch step promotes it. (2) Licensing as `license` (raw token) + `license_tier` (`open|non_commercial|restricted|unknown`) + derived `extraction_allowed`. A paper can be `full_text_unverified` yet `extraction_allowed = False`.
- **Alternatives:** boolean `full_text` (rejected — conflates existence/reachability/rights); two-state `full_text|abstract_only` with a verified flag (rejected — the user chose the explicit three-state enum to propagate uncertainty downstream).
- **Consequences:** More enum handling everywhere, but faithfulness-preserving: downstream weighting can distinguish verified full text, unverified full text, and abstract-only, and respect extraction rights separately.

## ADR-0003 — Storage: schema-and-contracts now, container deferred
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** Phase 1 lists "pgvector setup," but embeddings/semantic search aren't consumed until the Retriever agent in Phase 3. Standing up a live DB now would front-load infra and make every Phase 1 test run depend on Docker.
- **Decision:** Define SQLAlchemy models + Alembic migration for `papers`/`paper_embeddings` and the `docker-compose.yml` in Phase 1, but keep tests DB-free (import/introspection only). Stand up the container and wire the repository in Phase 3 when there's data to justify it.
- **Alternatives:** full stack now (rejected — front-loads infra, Docker dependency in CI); defer pgvector entirely (rejected — leaves the storage schema undesigned).
- **Consequences:** Phase 1 stays fast and network/Docker-free; the storage schema decision is still locked. Repository wiring is Phase 3 work.

## ADR-0002 — State layer: hybrid (shared PipelineState + per-node contracts)
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** LangGraph is idiomatic with a single accumulating typed state, but the project requires each node's input/output schema to be "explicit and testable in isolation," and the eval harness leans on pure node functions.
- **Decision:** Define a shared `PipelineState` for LangGraph-native orchestration AND per-node `Input`/`Output` Pydantic pairs, with adapters (`project_*`, `merge_*`) projecting/merging. Nodes are pure `node(input) -> output`. Merges are targeted and non-destructive (partial updates preserve untouched entries — a tested contract).
- **Alternatives:** single accumulating state only (rejected — implicit field coupling, harder isolated testing); per-node contracts + thin orchestration state only (rejected — more boilerplate, less LangGraph-native).
- **Consequences:** Slightly more wiring; in exchange, every node is independently unit-testable and the graph state still serializes cleanly for jobs/tracing.

## ADR-0001 — Repo structure: backend-forward monorepo
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** The system has a substantial Python backend (agents, NER, eval) and a Next.js frontend. Solo portfolio project targeting reviewability and demoability.
- **Decision:** One git repo, `backend/` and `frontend/` siblings, with top-level `docs/`, `evals/` (later), `docker-compose.yml`. Backend is the bulk of the work.
- **Alternatives:** two separate repos (rejected — coordination overhead, worse review/demo for a solo project); Python workspace monorepo with split installable packages (rejected — upfront ceremony not yet justified; can split later if a package boundary earns it).
- **Consequences:** Everything versioned together and visible in one place. If the backend later needs hard internal boundaries, revisit toward a workspace layout.
