## ADR-0013 — Chemical–disease relation extraction does not get its own phase: same-sentence pairing captures 77% of a ceiling that upstream entity loss already caps
- **Date:** 2026-07-29
- **Status:** Accepted — **conditionally revisitable** (see Consequences)
- **Context:** ADR-0008 defines a cluster as papers about the same chemical–disease relationship, but nothing in the pipeline decides which chemical pairs with which disease inside a paper. The cheapest answer is the full cross product of linked chemicals × linked diseases, which is obviously lossy on precision; the open question was **how lossy, and whether closing the gap requires a real CID relation extractor** with a model, a training set and its own phase. That question was answerable without assumption because **`CDR_Data.zip` ships gold CID relations** — 4-field `PMID/CID/chemMeSH/disMeSH` records that the 6-field mention parser had been silently skipping since Phase 2. (An earlier note in this project asserted BC5CDR "does not label which papers belong together." That was wrong; it was corrected and verified against the real corpus before any of this work proceeded.) Two arms were measured: **Arm A** synthesizes entities from gold mentions + gold ids over all **1500** documents; **Arm B** runs the real NER + linking pipeline, held out to **Test-500** because the NER checkpoint was fine-tuned on BC5CDR's training split — a correctness requirement, not a sample-size preference. Scoring is at three levels, with **paper-pair primary**, because `ContradictionFinding` is `(paper_id_a, paper_id_b, label, rationale)` and a pair is the Critic's unit of work.
- **Decision:** **Do not scope CID relation extraction as a phase. `SameSentencePairing` is the pairing strategy of record.** Same-sentence co-occurrence beats the cross product on **every arm and every metric level** — paper-pair F1 **0.4305 → 0.6204** on gold entities/1500 and **0.5484 → 0.6327** on the real pipeline/500 — and roughly **halves the Critic's workload**, with distinct Critic calls dropping 7066 → 3571 on Arm A (1.98×) and 460 → 279 on Arm B (1.65×), a direct cost result since every call becomes an LLM invocation in Phase 5. The rejection of relation extraction rests on three reasons, in order of weight: **(1) the binding constraint is upstream, not in pairing** — of 1066 gold CID relations in Test-500, **430 (40.3%) have an endpoint the real NER + linking pipeline never produced for that paper**, and no pairing mechanism, heuristic or learned or perfect, pairs an entity that was never extracted; **(2) the free heuristic already captures 77.0% of a precision-perfect ceiling at zero model cost** — an oracle granted perfect pairing over Arm B's *real* entity set scores F1 **0.8212** against same-sentence's **0.6327**, so the entire pairing-strategy question is worth at most **+0.1886 F1** and three quarters of it is already taken by one sentence-boundary lookup; **(3) the realistic win is smaller than +0.1886**, because part of same-sentence's recall is *accidental* co-clustering through wrong shared keys, which a precision-oriented extractor would give up.
- **The entity-conditioned oracle is precision-perfect and recall-capped, NOT a hard F1 bound.** Stated explicitly because the same class of error was made and corrected inside this very sub-project. The oracle's precision is **1.0000 by construction** — it emits only gold-true keys — so it bounds recall and nothing else. The **empirical proof, not merely the structural argument**: same-sentence's paper-pair recall is **0.7346, which exceeds the oracle's 0.6967.** A mechanism already measured beats the "ceiling" on recall, because paper-pair recall credits a co-clustered pair whenever two papers share *any* predicted key, so a **wrong** key held by both papers can accidentally co-cluster a genuinely gold-related pair — a win the oracle forgoes. A mechanism trading precision for recall can therefore exceed F1 0.8212. **The 77.0% figure is a fraction of a one-sided construction and must always be cited as such.**
- **The spec's original "Arm A is a ceiling for Arm B" claim was false, and is kept with its refutation rather than edited away.** The arms run on different corpora (1500 vs 500) and were never directly comparable; made apples-to-apples they **invert** — Arm A restricted to Test-500 scores same-sentence P 0.4279 / R 0.9005 / **F1 0.5802**, *below* the real pipeline's P 0.5556 / R 0.7346 / **F1 0.6327**. Granting perfect entities can only *add* candidate pairs, and adding candidates against a fixed gold pair set can only cost precision. The reusable rule: **any construction that improves recall by granting something correct, without touching what the system emits wrongly, is a ceiling for recall alone — before calling anything a ceiling, ask what it can make WORSE.** A corollary finding is that NER + linking act as an unintended **precision filter** (the entities they resolve are the more canonical ones, likelier to carry an annotated relation) — a property of **this corpus and this gold standard**, and emphatically **not** an argument that noisier extraction is better or that better NER is unnecessary. The 40.3% endpoint loss above is the direct measure of what better NER would buy.
- **Alternatives:** (1) Build a CID relation extractor as Phase 3D (rejected — it competes for at most +0.1886 F1, realistically less, on the 59.7% of relations whose endpoints survive extraction, and the standing rule is no infrastructure without a demonstrated consumer; there is no Critic yet). (2) Ship the cross product and let the Critic filter (rejected — it costs 0.1899 F1 on Arm A and roughly doubles the Critic's call count, i.e. doubling LLM spend to recover precision a free heuristic already has). (3) Redefine the cluster key as a single concept rather than a chemical–disease pair (rejected outright at the design stage — single-concept keys do not solve the pairing problem, they redefine clustering into something that no longer serves the reason it exists per ADR-0008; that is abandoning the goal, not simplifying it). (4) Loosen same-sentence to same-paragraph or an N-token window (not measured, not rejected — a cheap sweep, but the headroom above caps what any pairing tweak can win).
- **Interpretation caveat on the precision figures — and what it does not license:** gold CID is **narrower than co-mention**, since BC5CDR annotates a chemical–disease pair only where the abstract asserts causal induction, so some pairs scored false-positive are genuine co-mentions that simply are not CID relations. That corrects **how the precision number should be read**; it does **not** make low precision matter less practically. The Critic's actual task — judging whether two papers contradict each other about a drug–disease effect — *is* the narrow, causal-relation-shaped task BC5CDR annotates, and a co-mention that is not a CID relation is still a wasted Critic call.
- **Placement — why `biolit/cluster/` is in the production package despite having no production caller yet.** It currently has exactly one non-test consumer, the eval itself, which on its face engages the standing "no infrastructure without a demonstrated consumer" rule that kept ADR-0011's ingest and ADR-0012's fallback linker on unmerged branches. **The rule's real discriminator is whether the module's value was contingent on the measurement's outcome.** For the fallback linker it was: the measurement rejected it, so the module was worthless. Here it is the opposite — the measurement's outcome is that same-sentence pairing **wins**, making `biolit/cluster/` the accepted Phase 3 implementation; `Cluster` and `PipelineState.clusters` have been domain types since Phase 1, so the interface was designed rather than invented for this eval; and the package is ~175 lines of pure stdlib adding no dependency, artifact or model. Decisively, moving it under `biolit_evals/` would break this eval's stated premise that **both arms run the production code path** rather than a parallel gold-only implementation — which is ADR-0010's argument verbatim (the eval exists to measure the production path). **The genuine gap is wiring, not location: nothing populates `PipelineState.clusters` yet.** This note exists so a future reader applying the consumer rule mechanically does not delete a module the measurement said to ship.
- **Consequences:** `EVAL_REPORT.md` carries the three-level tables, the corrected ceiling analysis, the entity-conditioned oracle, all three anchor definitions and the reproduction recipe, so the result stands without the code. **Three harness anchors gate every run on the real path**, not merely in tests: `assert_key_recall_anchor` requires `cross_product` key recall to round to exactly 1.0000 on gold entities (the cross product emits every combination by construction, so a miss means the harness lost gold); `assert_gold_cluster_anchor` requires gold cluster counts of 500→80 and 1500→325, a **loader-correctness check on `load_bc5cdr_cid_relations`, explicitly not a clustering-quality check**; and `assert_full_reachability_on_gold_entities` requires the oracle to reach **every** gold relation on Arm A, since a gold relation's endpoints are themselves gold mentions — which gates the ceiling the decision rests on. A fourth guard, `assert_dataset_size`, halts any run whose corpus size contradicts its `dataset` tag, closing a hole where an Arm B run over anything but exactly 500 documents was scored and logged with no anchor firing at all. **Cluster-size capping is carried forward as a design consideration, not built:** `top5_pair_share` reaches **0.503** on Arm B same-sentence — half of all cluster comparisons come from five clusters, the largest contributing 55 (11 papers), and 378 from one 28-paper cluster on Arm A — so a cap is clearly motivated, but there is no Critic to protect and building it now would violate the same rule this ADR applies to relation extraction. The measurement that motivates it is committed and waiting. **Conditional revisit:** reopen if the Critic, once built, shows measurable harm traceable to same-sentence's false pairs specifically — as distinct from the 40.3% lost upstream, which relation extraction cannot address. Alternative #4 was never measured, so the 77.0% figure prices *same-sentence*, not the best achievable heuristic.
- **⭐ Standing project-level finding — this is the second time upstream entity loss has been the dominant, downstream-unrecoverable bottleneck.** It is named here rather than left implicit across two ADRs. In **Phase 3C** the mechanisms that looked like the answer were fragment merging and then an embedding fallback linker; measurement showed the dominant loss was **1679 gold mentions whose span NER got exactly right but which linked to nothing**, priced at **+0.0821 concept F1 — 39× the fragment-merge ablation and the largest recoverable loss measured anywhere in this project** — of which the fallback then realized only **24%**, at 53.9% mention precision (ADR-0012). In **Phase 3 clustering** the mechanism that looked like the answer was a CID relation extractor; measurement showed **40.3% of gold relations lose an endpoint before pairing is ever consulted**. Both times the loss was **downstream-unrecoverable**: no linker fixes a span NER missed, and no pairing strategy pairs an entity that does not exist. Two instances of one finding, not two coincidences. **The operative consequence: entity recall — NER coverage and linking coverage — is this pipeline's dominant constraint, and downstream reasoning components must be priced against an entity-conditioned ceiling rather than an oracle-entity one, or they will be scoped against headroom that does not exist.** The entity-conditioned oracle here is the concrete template, and it should be the default construction for pricing Phase 4 and Phase 5 components.

## ADR-0012 — The embedding fallback linker is documented, not shipped: a real effect, too weak and too costly to justify now
- **Date:** 2026-07-28
- **Status:** Accepted — **conditionally revisitable** (see Consequences)
- **Context:** ADR-0011 redirected the alias-gap question to a genuine generalization sub-problem, and the ceiling split showed **paraphrase is ~99% of the +0.0821 oracle ceiling**. That ceiling is **recall-only by construction** (granting gold ids converts `fn`→`tp` and cannot add a false positive, which is why `fp` stayed pinned at 312 across all four oracle variants), so its distance from reality was unmeasured. The open question was not "is there a gap" but **"what does a real linker cost in precision to close any of it."** Measured over the **full 3209-mention NIL population** — not the favorable 1136-mention paraphrase slice — because a real linker cannot see gold alignment and fires on all 3209, and because a slice-scoped figure would be silent about exactly the false positives the system would pay.
- **Decision:** **Do not ship the embedding fallback, and do not merge the branch that measured it.** The effect is **real and correctly attributed** — this is explicitly *not* a repeat of ADR-0011's null. SapBERT (`cambridgeltl/SapBERT-from-PubMedBERT-fulltext`, all 552,756 alias rows, exact chunked cosine, breakpoint-exact threshold sweep) peaks at **F1 0.7897 (+0.0200)** against the 0.7697 dictionary baseline, and beats the character n-gram TF-IDF control **3.4×** (+0.0200 vs +0.0058). That control existed so a gain could not be credited to a model until plain fuzzy string matching was ruled out; it was not ruled in. **The mechanism is semantic generalization, not string similarity, and those are materially different builds.** The rejection is on **cost and fragility relative to value**, and rests on three numbers rather than the ΔF1: **(1) mention-level precision at the peak is 53.9%** (365 correct of 677 fired) — every second link is wrong; **(2) `mentions_wrong / Δfp` is 2.89** (312 wrong mention links cost only 108 *new* false positives), so the positive F1 delta exists only because document-level set semantics absorb ~2.9 wrong links per error the metric reports; **(3) realized gain is 24% of the oracle ceiling** (+0.0200 of +0.0821). Against that, shipping costs an ~849 MB fp16 index, a second BERT forward pass in the linking path, and a threshold that must be tuned — and at threshold 0 the mechanism scores **F1 0.7027, actively worse than not firing at all.** Label-constraining the candidates helps by +0.0017 and is free, so it is the right configuration if this is ever built.
- **Scope — this is a clustering verdict, not a pipeline verdict:** measured entirely against **document-level concept-set scoring**, the metric clustering consumes. It mirrors the abbreviation-expansion caveat (ADR-0011 consequences) **in the opposite direction**: there a mechanism looked worthless at concept level while genuinely correcting 543 mentions, so mention-level consumers were told not to inherit the rejection. Here the absorption that *rescues* the number for clustering is exactly what a mention-level consumer does not get. **Phase 4 (evidence attribution) and Phase 5 (contradiction detection) must not inherit this conclusion in either direction** — for them the statement is stronger and more negative: a concept id that is wrong roughly half the time is **unusable as ground truth for a specific claim**, and would need a much higher threshold (trading away most of the recall) or a better model first. Both should re-measure against their own metric.
- **Alternatives:** (1) Ship it at the argmax-F1 threshold (rejected — +0.0200 bought at 53.9% mention precision, on a metric that demonstrably hides 2.9× the error it reports; the standing rule is no infrastructure without a demonstrated consumer, and a mechanism whose value depends on the metric not seeing its mistakes is a weak consumer). (2) Ship the TF-IDF control instead, as the cheap non-neural option (rejected — +0.0058 is not worth a second index either, and it answers the wrong question: the control's job was attribution, not deployment). (3) Report the paraphrase-slice figure as the headline, where the same mechanism looks better at +0.0254 and 69.0% mention precision (rejected outright — **70.2% of the wrong links land on the 1530 non-gold-aligned NILs the slice cannot see**, and the slice overstates the full-population gain by 27% relative; this is the fourth instance of a favorably-selected population reporting a better number than the system would pay, after 91→11, 543→4, and 1136→431). (4) Improve the policy before deciding — per-label thresholds, margin-based abstention, calibration (deferred, not rejected: see Consequences).
- **Consequences:** The implementation stays on the unmerged branch **`phase-3c-fallback-measurement`** (`0f4eac7`..`fbcae08`), so `master` carries no dead module while the experiment stays recoverable — the same handling as `phase-3c-mesh-alias-enrichment`. The `EVAL_REPORT.md` section carries the full curve, both anchor validations, the reproduction recipe, and the two anomalies that were chased down, so the result is reproducible without the code. **Conditional revisit — this is deferred, not closed.** Reopen if **clustering later shows measurable harm traceable to the missing paraphrase-linked concepts** (the concrete trigger, mirroring ADR-0011's conditional framing), or if a stronger policy is worth pricing: alternative #4 above was never measured, so the 24%-of-ceiling figure prices *top-1 with one global threshold*, not the best achievable embedding fallback. **The concept→label map stays on the branch too**, and does not get quietly promoted: it is built from the same CTD download as the alias table in the same run (**0 orphans**, verified rather than assumed; **79 multi-label concepts**, the empirical justification for `dict[str, set[EntityLabel]]` over a last-write-wins scalar, which would have silently mislabeled all 79). It is well-tested and independently useful, but its only consumer is the rejected fallback, so promoting it would violate the same rule this ADR is applying. If a consumer appears, it is the cheapest piece of this branch to extract.

## ADR-0011 — Dictionary enrichment from MeSH is rejected: the alias gap is not an alias-coverage gap
- **Date:** 2026-07-25
- **Status:** Accepted
- **Context:** The exact-span link audit found **1679 gold mentions whose span NER got exactly right but which linked to nothing**, and the oracle ceiling priced that population at **+0.0821 concept F1** — 39× the fragment-merge ablation, and the largest recoverable loss measured anywhere in this project. Reasoning from the structural fact that *every one of those mentions has a MeSH concept by definition* (the gold assigns one), I concluded the gap was **alias coverage**: fixable by a richer, still-deterministic dictionary, with no model. That inference was explicit in `EVAL_REPORT.md`, and it drove the decision to test MeSH's own entry terms before scoping any embedding fallback.
- **Decision:** **Reject dictionary enrichment from MeSH, and do not merge the ingest that tested it.** MeSH `desc2026` + `supp2026` entry terms were ingested (streamed via `iterparse`; descriptor tree numbers under `C*`, `F03*`, `D*`; supplemental records of `SCRClass` 1 and 3 — note the real attribute is **`SCRClass`**, not `SupplementalRecordType`) and unioned with the CTD table. Measured model-free over all 9718 linkable BC5CDR gold mentions, it rescues **3 of the 2514 CTD-NIL surfaces (0.1%)** and breaks **0** previously-correct links. The cause is arithmetic: CTD contributes 551,669 aliases, MeSH 784,332, and their union only **819,422** — an overlap of ~517k, because **CTD's `MESHSynonyms` column already *is* MeSH's entry terms**. Enriching CTD from MeSH re-adds what CTD already had.
- **The correction this forces — "the concept exists" ≠ "the surface exists":** the inference above is **wrong**, and is kept in the report with a pointer to its refutation rather than edited away. A concept being present in MeSH does not imply a fuller alias list reaches it, because the missing surfaces are not absent synonyms. Validated as a genuine null and not a broken parse: the ingest yields **271,668 distinct concept ids**, and for **2448 of the 2510** surfaces that remain NIL the gold concept **is present** — only the surface is missing (62, or 2.5%, are genuinely absent, mostly outside the kept trees, e.g. `blood urea nitrogen`). Classifying the 2510: deterministic normalization **50 (2.0%)**, abbreviation-shaped **1024 (40.8%)**, paraphrase/other **1436 (57.2%)** — `TdP` → *Torsades de Pointes*, `NO` → *Nitric Oxide*, `cognitive deficits` → *Cognition Disorders*, `hepatic injury` → *Chemical and Drug Induced Liver Injury*. No controlled vocabulary enumerates author abbreviations or paraphrases, which is exactly why more vocabulary changed nothing.
- **Alternatives:** (1) Merge the ingest anyway, as a harmless superset (rejected — it adds a 62 MB download, a second artifact source and a streaming XML parser to production for a measured 0.1% gain; this project's standing rule is no infrastructure without a demonstrated consumer, and a falsified hypothesis is not one). (2) Try UMLS instead (rejected for now — UMLS is licence-gated, and the failure mode here is not vocabulary size but surface form; the same overlap argument applies to any controlled vocabulary). (3) Loosen the tree/class scope filter to recover the 62 absent concepts (rejected — 2.5% of a population whose overall rescue rate is 0.1%, and loosening it admits anatomy/organism surfaces a CHEMICAL/DISEASE linker can match wrongly).
- **Consequences:** The implementation is kept on the unmerged branch **`phase-3c-mesh-alias-enrichment`** (commits `a246703`, `5e2d3d5`), so master carries no dead module while the experiment stays recoverable; this ADR plus the EVAL_REPORT section carry enough detail (sources, filters, counts, validation) to reproduce the result without it. The finding **redirects rather than closes** the question: the gap splits into a deterministic sub-problem (**abbreviations, ~41%+ — addressable by in-document expansion, since these abstracts define abbreviations on first use**) and a genuine generalization sub-problem (**paraphrase, ~57%**). Only the second is embedding territory, so the fallback's addressable share is materially smaller than the +0.0821 ceiling implies. Sizing that split is the prerequisite for scoping a fallback at all.

## ADR-0010 — Long documents are windowed inside the NER layer, not by callers
- **Date:** 2026-07-24
- **Status:** Accepted
- **Context:** The first full-scale end-to-end eval run crashed with `RuntimeError: The size of tensor a (549) must match the size of tensor b (512)`. The NER checkpoint's tokenizer declares no `model_max_length`, so it never truncates, while BERT-family position embeddings cap input at 512 tokens. **11 of the 500 BC5CDR test abstracts (2.2%) exceed that** (median 267, max 722). It had never surfaced because every prior measurement — Phase 2 NER, Phase 3A linking, the domain sample — ran on *sentences*. Phase 4's Extractor feeds whole abstracts, so this would have crashed on roughly 2% of real papers in production. This decision was made during Phase 3B execution and is **not** in that phase's plan, which is why it is recorded here.
- **Decision:** Window inside `NerModel`, so `extract_entities` is safe on text of any length and every consumer inherits the fix without changing a call site. The alternative — windowing in the eval's `predict` function — was rejected outright: the eval exists to measure the production path, so fixing it only in the eval would have made the report claim success against a code path production does not run. Windows are packed from **whole sentences** (an entity practically never spans a sentence boundary, making it the safest cut point); consecutive windows **overlap by one sentence**; offsets are shifted back into document coordinates; and results are de-duplicated, with any span strictly contained in another span of the same label dropped, because overlapping windows can otherwise emit nested spans that cannot occur on single-window input.
- **Alternatives:** (1) Truncate to 512 tokens (rejected — silently discards entities in the tail, and the discarded region is exactly where conclusions live). (2) Exclude over-long documents from the eval (rejected — biases the corpus toward shorter abstracts and leaves the production crash live). (3) Rely on the HF pipeline's own chunking (rejected — token-classification pipelines do not window automatically, which is precisely why the raw tensor reached the model).
- **Consequences:** `extract_entities` handles arbitrary-length text, and end-to-end numbers on long documents are therefore not directly comparable to Phase 2's sentence-level NER F1. **Two known limits, recorded rather than hidden:** (a) the one-sentence overlap only materializes when a window holds more than one sentence — a single sentence filling an entire window has hard-cut boundaries; at the 450-token budget against normal sentences every internal boundary is spanned, but the guarantee is conditional, not universal. (b) A whitespace-free run longer than the budget is split at character granularity, which can cut an entity, because the alternative is losing the whole document to a tensor-size error. Both are pinned by tests, including a paired test showing the overlap guarantee genuinely fails when overlap is disabled.

## ADR-0009 — A merged fragment candidate may only fill a NIL gap, never overwrite a link
- **Date:** 2026-07-23
- **Status:** Accepted
- **Context:** `canonicalize()` originally applied a merged fragment candidate **unconditionally** to every entity it spanned (the "merged candidate first, first hit wins" ordering written into the canonicalization spec §4). That ordering is unsafe because `merge_fragments` is deliberately permissive: a connector-joined run of adjacent same-label spans merges when **any** token is "fragment-shaped" (all-caps, contains a digit, or is under three characters). Real clinical notation satisfies that trivially — `ASA/clopidogrel`, `HTN/DM`, and `vitamin D-calcium` all merge, alongside the desirable `TMP-SMX`. Combined with unconditional application, a spurious merge that happened to resolve to a real alias would assign **one wrong shared MeSH ID to several entities that each linked correctly on their own**. This is the worst failure mode available in this layer: it is silent (nothing errors), it corrupts multiple entities at once, and it does so at exactly the seam clustering keys on — so it would surface as papers wrongly clustered *together*, the mirror image of the ADR-0008 failure. It was caught by whole-branch review rather than by tests: the "adversarial must-not-merge" test used `aspirin-warfarin`, where *neither* token is fragment-shaped, so it never exercised the permissive branch it was written to guard.
- **Decision:** `canonicalize()` looks up **every entity on its own surface first**. A merged candidate's concept is then applied **only to constituents whose individual lookup returned NIL**. A merge can fill a gap; it can never overwrite a link. A regression test pins this: two individually-linkable entities keep their own concepts even when their merged surface also resolves (verified failing against the previous implementation — both entities took the merged concept — and passing after).
- **Alternatives:** (1) Tighten `merge_fragments` so it cannot propose these runs (rejected *as the primary fix* — it trades one hand-tuned heuristic for another and cannot be validated without data; deliberately deferred until the merge-path eval shows where the rule is actually too permissive). (2) Keep merge-first and accept the risk (rejected — silent, multi-entity, and located at the clustering seam). (3) Require a merged candidate to outrank individual links by confidence (rejected — the dictionary linker returns no confidence score, so there is nothing to rank on).
- **Consequences:** The ADR-0008 motivating case is unaffected: `GLP` and `1RA` are each NIL alone, so the merged concept still applies to both. The permissive heuristic's blast radius is now bounded to NIL gaps, which is *why* tightening it is deferred rather than urgent. **Caveat:** the reported linking metrics do not exercise this path at all — the scorer calls `Linker.link()` on gold surfaces and never calls `canonicalize()` — so this ordering is currently guaranteed by unit tests only. Measuring it is the merge-path eval, which is scoped ahead of clustering precisely because some current NIL cases may be recoverable by better merge behavior before any fallback linker is justified.

## ADR-0008 — Entity canonicalization is a Phase 3 prerequisite, not a clustering subtask
- **Date:** 2026-07-22
- **Status:** Accepted (decision to prioritize; design deferred to Phase 3)
- **Context:** Phase 2's domain error analysis (`biolit_evals.error_analysis --dataset domain`, transcript in `docs/EVAL_REPORT.md` "Interpreting the gap") found that of 57 errors on the domain sample, **34 (60%) are boundary disagreements on entities the model did detect** — not failures to find an entity. The dominant pattern is drug-class abbreviations and hyphenated compound names fragmenting under the subword tokenizer, which `aggregation_strategy="simple"` does not reassemble: gold `CFD` predicted as `CF` (×10 in the sample), `GLP-1RAs` split into `GLP` + `1RA`, `SGLT2is`/`DPP4is` partially spanned, `sodium-glucose cotransporter-2 inhibitors` truncated to `sodium-glucose`. Crucially, **this fragmentation is invisible as an NER error to any downstream phase.** Phase 3 clusters papers by shared entities and Phase 5 detects contradictions within those clusters; if `GLP-1RAs` fragments into `GLP` and `1RA` *inconsistently across papers*, entity-keyed clustering silently splits papers that belong together. The failure surfaces as **missing clusters** — an absence — not as a flagged mismatch anywhere. A green NER metric and a plausible cluster count can coexist with this defect. (An unknown share of the 0.81→0.66 headline-vs-domain gap is a tokenization-format confound rather than model weakness — see the eval report — but that caveat does not weaken this finding: the fragmentation pattern is real in the predictions regardless of how much of the *score* gap it explains, and it is the fragmentation, not the score, that breaks clustering.)
- **Decision:** Treat entity canonicalization (mapping surface variants and fragmented spans to a stable normalized key) as a **prerequisite that must exist before entity-keyed clustering is trusted**, not as a refinement layered on afterward. Scope it as its **own brainstorm → spec → decision trail in Phase 3, separate from retrieval/clustering design** — it is a distinct problem (string/ontology normalization) and consequential enough to earn its own decisions rather than being folded in as a clustering implementation detail. This ADR records *why* and *that* it is prioritized; it deliberately does **not** commit to a *how*. The eventual mechanism — abbreviation-aware span merging, dictionary/ontology linking (e.g. MeSH/UMLS), learned normalization, or some combination — is a Phase 3 decision to be made against real clustering behavior.
- **Alternatives:** (1) Fold normalization into clustering as a sub-step (rejected — its design tradeoffs, e.g. ontology dependence and normalization aggressiveness, deserve their own decision trail; burying them makes the clustering ADR do two jobs and hides the tradeoff). (2) Defer normalization until a visible clustering failure forces it (rejected — the failure mode is an *absence* of clusters, which is exactly the kind of silent wrongness the eval work has repeatedly shown does not announce itself; waiting means shipping a plausible-looking but wrong clustering and hoping to notice). (3) Rely on a stricter `aggregation_strategy` or a different checkpoint to stop fragmenting (rejected as *the* answer — may reduce fragmentation but cannot guarantee cross-paper consistency of the surviving surface forms, which is the actual clustering requirement; still worth evaluating as one input to the Phase 3 design).
- **Consequences:** Phase 3 carries an explicit, separately-tracked canonicalization workstream ahead of clustering, with its own spec and ADR. The domain gold sample is intentionally **not** broadened yet (see project notes): a broader domain eval set will be re-derived *after* canonicalization exists, so the annotation effort is spent once against the normalized pipeline rather than twice — mirroring how the ADR-0007 abstract-truncation fix already forced one re-annotation. The `Entity.label` field was tightened to the `EntityLabel` `StrEnum` (applying ADR-0005) as a first, mechanical step toward type-checking entity attributes at the Phase 4 seam; normalization will add a canonical-key/identifier axis to `Entity` in Phase 3, and that shape is deferred to its brainstorm.

## ADR-0007 — Structured abstracts are concatenated with section labels
- **Date:** 2026-07-22
- **Status:** Accepted
- **Context:** `PubMedClient` parsed abstracts with `article.findtext(".//Abstract/AbstractText")`, which returns only the *first* matching element. PubMed structured abstracts carry one `<AbstractText>` per section, so we silently kept only the opening section. Verified live on PMID 27295427 (LEADER trial): 156 of 2259 characters — 7% — with METHODS, RESULTS, and CONCLUSIONS discarded. Phase 1's tests all passed because every committed cassette happened to contain an unstructured abstract; the bug surfaced only when a human-facing task read real pulled text. This is severe for this project specifically: the system exists to extract findings and detect contradictions, and those claims live in RESULTS/CONCLUSIONS.
- **Decision:** Concatenate all `<AbstractText>` elements in document order. Use `"".join(el.itertext())` per element so nested inline markup (`<i>`, `<sup>`) is preserved rather than truncating the section at its first child tag. When an element carries a `Label`, prefix that section `"<LABEL>: "` — this is how PubMed itself renders structured abstracts, so it stays faithful to the source and preserves section structure for downstream extraction. Join sections with `"\n"`. Unstructured abstracts and absent abstracts keep their existing behavior exactly (plain text; `None`).
- **Alternatives:** join section texts without labels (rejected — discards structure that the Extractor and contradiction phases can use, and PubMed renders the labels anyway); keep a list of sections on `Paper` (rejected for now — changes the Phase 1 model contract and no consumer needs per-section access yet; revisit if one does).
- **Consequences:** Abstract text is complete. **Caveat:** because the `"LABEL: "` prefixes are synthesized, character offsets into `Paper.abstract` no longer index any contiguous string in the source document. For a citation-backed system that quotes excerpts, any future offset-based quoting into an abstract must account for this — prefer quoting the section text, not raw offsets. The Phase 2 domain gold sample was rebuilt from post-fix abstracts; the pre-fix sample was discarded rather than patched.

## ADR-0006 — Domain-sample NER annotation is blind and from-scratch
- **Date:** 2026-07-21
- **Status:** Accepted
- **Context:** Phase 2's hand-annotated domain sample exists to test the NER model *independently* of the BC5CDR benchmark — specifically to surface where the model fails on our own corpus. A model-assisted "pre-label then human-verify" workflow is faster but introduces anchoring bias: annotators are measurably worse at catching false negatives (entities the model missed) when reviewing a pre-populated candidate list than when reading cold. That false-negative blindness is exactly the failure mode the sample is meant to catch.
- **Decision:** Annotate `evals/gold/domain_sample.jsonl` blind and from scratch — reading raw abstract sentences with no model predictions visible. Finalize the gold file first, then run the model and score. Any comparison of model-influenced labeling is a separate, clearly-labeled secondary artifact, never a substitute for the blind pass. Record source PMIDs/paper ids as provenance on every annotated sentence. Document both the single-annotator limitation and this methodology in the eval report.
- **Alternatives:** model-assisted annotation then human review (rejected — undermines the sample's sole purpose by biasing it toward the model's own recall gaps); benchmark-only eval (rejected earlier — loses the "works on my actual corpus" signal).
- **Consequences:** More annotation effort, but the domain F1 is an honest independent check. Provenance keeps the sample traceable if papers are re-pulled. The unbiased headline number remains the BC5CDR test split; the domain sample is a supporting cross-check.

## ADR-0005 — String-valued enums use `enum.StrEnum`
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** The Phase 1 plan wrote enums as `class X(str, Enum)`, but the project's ruff ruleset includes `UP`, whose `UP042` rule flags that pattern and fails the required lint gate. The plan mandated both the pattern and a green gate — a conflict surfaced during Task 2.
- **Decision:** All string-valued enums inherit from `enum.StrEnum` (Python 3.12). Behavior is identical for pydantic JSON serialization and `is`/`==` comparisons; the full `UP` ruleset stays active rather than suppressing a valid rule.
- **Alternatives:** keep `(str, Enum)` and add `UP042` to ruff `ignore` (rejected — silences a legitimate modernization rule to preserve example code).
- **Consequences:** `Source`, `TextType`, `LicenseTier` (Task 2) and `ContradictionLabel` (Task 3) use `StrEnum`. Applies to all future enums.

## ADR-0004 — Full-text signalling: three-state `text_type` + separate license axis
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** A paper's full text may *exist* yet not be *reachable yet* (bioRxiv `jatsxml` URL can 404 for freshly-posted preprints; PMC membership is not a fetch), and *existence* is independent of *permission to extract/display* (verified live: a medRxiv record with a full `jatsxml` path but `license: cc_no`). A boolean `full_text: bool` conflates all three concerns and would silently over-promise to the Synthesis agent.
- **Decision:** Model two independent axes. (1) `text_type` enum with three states — `full_text_available` (exists AND verified reachable), `full_text_unverified` (pointer exists, unconfirmed), `abstract_only`. Ingest never yields `full_text_available`; a later verification/fetch step promotes it. (2) Licensing as `license` (raw token) + `license_tier` (`open|non_commercial|restricted|unknown`) + derived `extraction_allowed`. A paper can be `full_text_unverified` yet `extraction_allowed = False`.
- **Alternatives:** boolean `full_text` (rejected — conflates existence/reachability/rights); two-state `full_text|abstract_only` with a verified flag (rejected — the user chose the explicit three-state enum to propagate uncertainty downstream).
- **Consequences:** More enum handling everywhere, but faithfulness-preserving: downstream weighting can distinguish verified full text, unverified full text, and abstract-only, and respect extraction rights separately.

## ADR-0003 — Storage: schema-and-contracts now, container deferred
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** Phase 1 lists "pgvector setup," but embeddings/semantic search aren't consumed until the Retriever agent in Phase 3. Standing up a live DB now would front-load infra and make every Phase 1 test run depend on Docker.
- **Decision:** Define SQLAlchemy models + Alembic migration for `papers`/`paper_embeddings` and the `docker-compose.yml` in Phase 1, but keep tests DB-free (import/introspection only). Stand up the container and wire the repository in Phase 3 when there's data to justify it.
- **Alternatives:** full stack now (rejected — front-loads infra, Docker dependency in CI); defer pgvector entirely (rejected — leaves the storage schema undesigned).
- **Consequences:** Phase 1 stays fast and network/Docker-free; the storage schema decision is still locked. Repository wiring is Phase 3 work.

## ADR-0002 — State layer: hybrid (shared PipelineState + per-node contracts)
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** LangGraph is idiomatic with a single accumulating typed state, but the project requires each node's input/output schema to be "explicit and testable in isolation," and the eval harness leans on pure node functions.
- **Decision:** Define a shared `PipelineState` for LangGraph-native orchestration AND per-node `Input`/`Output` Pydantic pairs, with adapters (`project_*`, `merge_*`) projecting/merging. Nodes are pure `node(input) -> output`. Merges are targeted and non-destructive (partial updates preserve untouched entries — a tested contract).
- **Alternatives:** single accumulating state only (rejected — implicit field coupling, harder isolated testing); per-node contracts + thin orchestration state only (rejected — more boilerplate, less LangGraph-native).
- **Consequences:** Slightly more wiring; in exchange, every node is independently unit-testable and the graph state still serializes cleanly for jobs/tracing.

## ADR-0001 — Repo structure: backend-forward monorepo
- **Date:** 2026-07-20
- **Status:** Accepted
- **Context:** The system has a substantial Python backend (agents, NER, eval) and a Next.js frontend. Solo portfolio project targeting reviewability and demoability.
- **Decision:** One git repo, `backend/` and `frontend/` siblings, with top-level `docs/`, `evals/` (later), `docker-compose.yml`. Backend is the bulk of the work.
- **Alternatives:** two separate repos (rejected — coordination overhead, worse review/demo for a solo project); Python workspace monorepo with split installable packages (rejected — upfront ceremony not yet justified; can split later if a package boundary earns it).
- **Consequences:** Everything versioned together and visible in one place. If the backend later needs hard internal boundaries, revisit toward a workspace layout.
